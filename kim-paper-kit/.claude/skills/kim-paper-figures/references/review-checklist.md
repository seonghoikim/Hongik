# 그림 검수 체크리스트 — 제출 전 확인

그림마다 아래 항목을 확인한다. 항목을 건너뛰지 않는다. 실패한 항목은 "무엇을 고쳤는지"를 한 줄 남긴다.

## A. 메시지와 구조

- [ ] 그림의 메시지가 한 문장으로 적혀 있다.
- [ ] 30초 테스트를 통과했다 (3초 보여 준 뒤 메시지를 말할 수 있다).
- [ ] 메시지와 무관한 상자, 주석, 색을 뺐다.
- [ ] 이 그림이 원서 대응 대상이면 `kim-mapping.md` 상태가 matched이거나 재작을 마쳤다.
- [ ] 프레임워크 전체를 보여 주는 그림이 장 안에 있다 (해당 장에 해당할 때).
- [ ] 수치 플롯은 핵심 비교만 남겼다.
- [ ] 공통 요소를 블록으로 떼지 않고 실행 순서대로 두었다. 공통은 색이나 표식으로 구분했다.
- [ ] 같은 노드가 여러 자리에 중복되어 있지 않다 (병합했다).
- [ ] 구도(무엇을 어디에 둘지)는 저자가 정했고, 그림은 코드로 그렸다.

## B. 양식

- [ ] 선과 글자는 검정이다. 강조 색은 빨강 하나다.
- [ ] 회색 단계는 두 개 이하다.
- [ ] 같은 색은 다른 그림에서도 같은 뜻이다.
- [ ] 플롯은 Okabe-Ito 팔레트, 도식은 검정·빨강·회색으로 섞지 않았다.
- [ ] 라벨은 명사구이고, 한 상자가 3줄 이내다.
- [ ] 열과 행의 순서는 알파벳·ID가 아니라 실행(그래프 위상) 순서다.
- [ ] 글꼴이 본문과 같은 계열이다. 한글 폰트가 깨지지 않는다.
- [ ] 계층 세분화 표나 확률 트리 같은 구조 문법을 우선 검토했다.

## C. 인쇄

- [ ] PNG 픽셀 폭이 인쇄 폭 × 300 / 72 이상이다. 368pt 기준 1534px 이상. (`check_figure_print.py --png`)
- [ ] 가장 작은 글자의 실효 크기가 8pt 이상이다. (`check_figure_print.py --font-px --canvas-px --print-width-pt`)
- [ ] 인쇄 폭은 게재지 레이아웃(전폭 또는 단)에서 확인했다. 추측하지 않았다.
- [ ] 흑백 미리보기에서 강조와 회색 단계가 구분된다. (`--gray-out`)
- [ ] 투명 배경이면 흰 배경 위에서 확인했다. 검은 배경이 보이면 추출 단계(SMask, 투명도 마스크)를 다시 본다.
- [ ] 그림 폭을 본문 폭 100%로 넣었다 (축소하지 않았다).

## D. 정확성

- [ ] 순서가 의미를 가지는 그림은 `verify_dot_order.py`로 좌표를 확인했다.
- [ ] 확률 트리는 갈림마다 합이 1이다. 값은 소스 데이터에서 생성했다.
- [ ] 수치는 소스 데이터와 일치한다. 손으로 옮긴 값이 없다.
- [ ] 약어는 본문에서 풀네임을 먼저 썼다. (교수님 지시 사례: 약어 대신 풀네임)
- [ ] 특화 명칭의 아래첨자는 표시 계층에서만 바꿨고, 데이터 키는 평문 그대로다.
- [ ] 그림 안 용어가 본문 용어와 같다.
- [ ] 이전 논문에서 확정된 그림 라벨과 충돌하지 않는다 (같은 BU나 같은 도메인의 표기).

## E. 파일과 버전

- [ ] 소스 파일(`.dot`, `.mmd`, `.html`, `.py`)이 저장소에 있다.
- [ ] 산출 파일(SVG 또는 PNG)이 소스에서 다시 만들어진다.
- [ ] 교수님께 보냈거나 제출한 버전은 `_v2`, `_v3` 새 이름으로 보존했다. 같은 이름을 덮어쓰지 않았다.
- [ ] 스크린샷은 원본과 주석본을 따로 두었다.
- [ ] 원서 그림을 본문에 그대로 싣지 않았다.
- [ ] 사용한 도구와 버전(Graphviz, matplotlib, Playwright 등)을 본문이나 부록에 적었다. 재현성을 요구받았기 때문이다.

## F. 캡션과 본문

- [ ] 캡션은 제목만 쓴다. 패널 설명과 결론은 본문 문단에 있다.
- [ ] 캡션 접두, 언어, 번호, 구두점이 투고 규정과 맞다.
- [ ] 본문에서 그림을 참조하는 형식이 규정과 맞다 (예: `Fig. n`).
- [ ] 그림 번호가 등장 순서대로 이어진다.

## G. Word 삽입

- [ ] `LockAspectRatio = True`를 `Width` 설정 전에 적용했다.
- [ ] 2단 문단에 들어가도 전폭 그림 폭이 강제되어 있다.
- [ ] 캡션은 그림 아래, 기존 캡션 스타일과 같다.
- [ ] PDF로 내보내 그림이 보이고 빈 상자가 없다. 쪽 하단에 큰 빈칸이 없다.
- [ ] 표가 쪽을 넘을 때 헤더가 반복되고, 행이 쪽 사이에서 잘리지 않는다.
- [ ] 결과는 새 이름의 DOCX로 저장했다.

## H. 발표용 (발표 자료에 넣을 때만)

- [ ] 발표용 그림은 논문용 원본과 다른 파일이다. 원본은 손대지 않았다.
- [ ] 실효 글자 크기를 슬라이드 표시 폭 기준으로 계산했다. 배율 보정을 빼먹지 않았다.
- [ ] 설명 글자는 11pt 이상이다.
- [ ] 슬라이드를 PNG로 내보내 눈으로 확인했다. 수치는 통과하는데 겹치는 경우가 있다.
- [ ] 세로로 긴 그림은 분할했거나 가로 배치로 바꿨다.

## 마감 직전 확인 (3가지)

1. 그림 목록을 열고 모든 그림에 소스와 산출물이 있는지 확인한다.
2. 본문에서 그림 번호와 캡션 번호가 맞는지 확인한다.
3. PDF 전체를 넘겨 보며 그림마다 "메시지가 보이는가"를 한 번 더 본다.
