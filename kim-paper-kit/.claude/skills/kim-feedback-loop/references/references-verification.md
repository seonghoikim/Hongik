# 참고문헌 검증

새 참고문헌을 원고에 넣는 절차, 번호가 밀릴 때의 처리, 검증 실패 대응을 다룬다.

## 1. 원칙

- 새 참고문헌은 DOI 가 CrossRef 에서 확인된 뒤에만 추가한다. 검색 결과 목록만 보고 추가하지 않는다.
- 이유: 언어 모델은 존재하지 않는 논문의 제목, 저자, 연도, 학술지를 그럴듯하게 만들어 낼 수 있다. 검증 소스를 Semantic Scholar 와 CrossRef 로 제한하면 이 위험을 줄일 수 있다.
- 기억으로 쓴 서지는 초안일 뿐이다. 반드시 DOI 로 대조한다.
- 참고문헌을 추가하는 것도 원고 변경이므로 체크리스트 항목으로 기록한다.

## 2. 절차

스크립트: `${KIT}/scripts/academic_search.py`

```
python "${KIT}/scripts/academic_search.py" search "<검색어>" --limit 5
python "${KIT}/scripts/academic_search.py" search "<검색어>" --json --source cr
python "${KIT}/scripts/academic_search.py" verify <DOI>
python "${KIT}/scripts/academic_search.py" cite <DOI> --format ijibc --ref <N>
```

1. `search` 로 후보를 찾는다. 영문과 한글 검색어 모두 된다. 영문 학술 용어가 결과가 더 좋은 경우가 많다.
2. 후보의 제목, 저자, 연도, 학술지, DOI 를 확인한다.
3. `verify <DOI>` 로 존재를 확인한다. 종료 코드 0 이면 VERIFIED, 1 이면 NOT FOUND 또는 INVALID, 3 이면 조회 실패(네트워크·서버 오류)다. 3 은 DOI 가 틀렸다는 뜻이 아니므로 잠시 후 다시 실행한다. 찾던 논문의 제목과 저자가 일치하는지 직접 대조한다.
4. `cite` 로 서지 문자열을 만든 뒤, 학술지 형식 규정에 맞게 고친다. 현재 구현에는 IJIBC 형식만 있다. 다른 학술지 형식은 `FORMATTERS` 딕셔너리에 함수를 등록한다. 등록하면 `--format` 선택지에 자동으로 나타난다.
5. 본문 인용 번호와 참고문헌 목록 번호를 함께 갱신한다.

선택 환경변수 (스크립트 파일에는 개인 정보를 넣지 않는다):
- `ACADEMIC_SEARCH_CONTACT`: CrossRef 에 보내는 연락처 문자열. 설정하면 CrossRef 의 우선 응답 풀을 쓸 수 있다.
- `SEMANTIC_SCHOLAR_API_KEY`: Semantic Scholar API 키가 있을 때만 설정한다.

## 3. 번호가 밀릴 때

원천 사례: 신규 참고문헌 3건을 앞쪽에 넣자 기존 [31]–[38] 이 [34]–[41] 로 밀렸다.

- 본문 인용 치환은 스크립트로 한 번에 한다. 매핑 표를 먼저 만들고, 정규식 `\[(\d+)\]` 에 매핑 함수를 넘겨 `re.sub` 를 한 번만 호출한다. 번호마다 `replace` 를 따로 돌리면 `[31]` → `[34]` 로 바뀐 뒤 다음 단계에서 그 `[34]` 가 다시 `[37]` 로 바뀌는 연쇄 치환이 생긴다. 치환 후 매핑 표를 답변서에 남긴다.
- 심사평에 나온 원 번호는 그대로 둔다. 답변서에서는 "원고 [33] → 수정본 [40]"처럼 두 번호를 연결한다. 심사자가 본 번호와 혼동되지 않게 하기 위해서다.
- 치환 후 검사:
  - 목록 항목 수 = 최대 번호
  - 본문에 나오는 번호가 모두 목록에 있다
  - 목록에 있는데 본문에서 인용되지 않은 항목이 없다
- 연속 인용 `[1][2][3]` 형식은 프로젝트 스타일을 따른다.

## 4. 검증에 실패했을 때

- NOT FOUND: DOI 오타일 수 있다. 제목으로 `search` 를 다시 해 올바른 DOI 를 찾는다. 그래도 없으면 쓰지 않는다.
- INVALID: DOI 형식(`10.숫자/...`)이 아니다. 주소 앞부분이 붙어 있으면 스크립트가 떼어 내지만, 형식이 맞지 않으면 DOI 를 다시 확인한다.
- 종료 코드 3 (네트워크 오류, 시간 초과, HTTP 오류): DOI 가 없다는 뜻이 아니다. 스크립트는 429 에 한 번 재시도한다. 그래도 실패하면 잠시 후 다시 실행한다. 3 을 NOT FOUND 로 읽어 DOI 를 버리지 않는다.
- 검색 결과가 없으면 검색어를 영문 학술 용어로 바꿔 다시 찾는다.
- DOI 는 맞는데 제목이나 저자가 다르면 다른 논문이다. 같은 DOI 라도 원고에 쓰는 서지는 검증 결과와 대조한다.

## 5. 주의

- 사전 인쇄본(arXiv 등)과 학술지 게재본은 서지가 다를 수 있다. 게재본 DOI 를 우선한다.
- 인용 목록에 올렸다고 해서 그 논문을 읽었다는 뜻은 아니다. 읽지 않은 논문에 구체적인 결과를 붙여 주장하지 않는다.
- 검증 결과 로그(verify 출력)를 작업 폴더에 남기면 나중에 어떤 DOI 를 어떻게 확인했는지 추적할 수 있다.
