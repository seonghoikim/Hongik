# 서브에이전트·워크플로 활용 패턴

여러 에이전트를 나눠 쓰는 기준, 교차 검증 방식, 압축 작업의 함정, 장시간 작업의 보호 방법을 다룬다.

## 1. 병렬화 기준

- 독립 작업은 병렬로 돌린다. 예: 그림 여러 개 생성, 참고문헌 검색과 본문 수정, 스타일 검수와 내용 검수, 전사와 이전 판본 비교.
- 단일 자원은 순차로 돌린다. 예: Word COM 인스턴스, 같은 파일을 편집하는 작업, 같은 체크포인트 폴더에 쓰는 작업.
- 의존 관계가 있으면 순차로 돌린다. 예: 전사 → 피드백 정리 → 체크리스트 → 새 판본.

## 2. 패턴 A: 독립 초안 → 교차 검증 → 원자료 대조

1. 같은 질문을 서로 독립된 에이전트 둘 이상에 준다. 관점을 다르게 지정한다.
2. 결과를 비교해 불일치 지점만 추린다.
3. 불일치는 원자료(데이터 파일, 원고 원문, 실행 로그)로 확인한 뒤 채택하거나 기각한다.
4. 기각한 지적도 근거와 함께 기록한다.

원천 사례: 교차 검토가 "두 값을 비교하는 것은 부적절하다"고 지적했다. 원자료를 확인하니 정답 2D 키포인트는 렌더 양식과 무관하므로 비교가 성립했다. 지적을 기각하고 근거를 체크리스트에 남겼다.

## 3. 패턴 B: 압축과 재작성은 기계 대조 후 수동 복원

- 분량을 줄이는 에이전트는 경계 마커(예: `{+ … +}`), 조건, 단서를 잘 잃는다. 원천에서 약 18% 압축 작업을 했을 때 단서가 빠진 곳이 생겼다.
- 압축 후 기계 대조를 한다.
  - 수치 집합이 같은가
  - 인용 번호의 순서가 같은가
  - 표의 행 수와 열 수가 같은가
  - 마커 개수가 같은가
- 어긋난 곳은 원문과 나란히 놓고 사람이 복원한다.

## 4. 패턴 C: 심사 시뮬레이션 (다중 페르소나)

- 심사자 페르소나를 여러 명 만든다. 예: 응용 관점, 방법론 관점, 실험 관점. 각 페르소나는 다른 지적을 낸다.
- 게이트를 둔다. 근거 없는 지적, 중복 지적, 원고 범위 밖 지적을 걸러낸다.
- 단계별 수를 기록한다. 원천 기록 예: 접수 26건 → 게이트 통과 24건 → 수용 21건.
- 완전성 비평가를 따로 둬서 빠진 지적이 없는지 본다.
- 원천 사례: 리뷰어 페르소나가 새로 쓴 절에서 잠복 오류 3건을 찾았다. 반례로 깨지는 명제 2건과, 정의가 빠진 조건 1건이다. 새 명제는 반례 탐색을 거친 뒤 쓴다.
- 시뮬레이션 결과는 참고용이다. 실제 심사 결과로 쓰지 않는다.

## 5. 패턴 D: 체크포인트로 장시간 작업 보호

- 한 번에 끝나지 않는 작업은 단위마다 결과를 저장하고, 완료된 단위는 건너뛰게 한다. `transcribe_meeting.py` 가 이 방식이다.
- 중간 결과는 임시 이름으로 쓰고 완료 후에 원래 이름으로 바꾼다. 쓰는 도중 중단돼도 반쪽 파일이 남지 않는다.

## 6. 서브에이전트 지시문 체크리스트

- 목표와 산출 파일의 새 이름. 기존 파일을 덮어쓰지 않는다 (versioning.md 1절).
- 금지 사항: 수치 임의 변경, 원고 외 파일 수정, 근거 없는 인용 추가, 원자료 삭제.
- 입력 자료의 절대경로.
- 보고 형식: 변경 파일 목록, 근거 위치(절, 표, 줄 번호), 확인하지 못한 사항.
- 원자료 확인 요구: 보고한 수치는 원자료에서 다시 계산해 쓴다.

## 7. 결과 채택 전 확인

- 서브에이전트 보고를 그대로 원고에 넣지 않는다.
- 수치는 원자료와 대조한다. 인용은 `verify` 로 확인한다 (references-verification.md). 서술은 체크리스트 항목과 대조한다.
- 여러 에이전트가 같은 파일을 건드렸다면 병합 전에 diff 를 확인한다.

## 8. 워크플로 예: 피드백에서 새 판본까지

1. 병렬: (a) 전사 (스크립트), (b) 이전 판본과의 diff 분석. 서로 의존하지 않는다.
2. 피드백 정리 초안 (순차: 전사 결과가 필요하다)
3. 체크리스트 작성 (순차: 피드백 초안과 diff 결과를 대조)
4. 새 판본 패치 (순차, 단일 파일)
5. 병렬: 스타일 검수와 내용 정합성 검수 (읽기 전용)
6. 결과 채택과 보고 (순차)

이 순서는 프로젝트 `CLAUDE.md` 의 서브에이전트 표를 따른 것이다.
