# Word COM 필수 규칙과 함정

DOCX 를 Word COM(pywin32)으로 조판할 때 지킬 규칙과, 실제로 겪은 사고를 모았다.
각 규칙은 **근거(사고)** 와 **방법** 을 함께 적었다. 사고의 수치는 예시이며, 같은 원리는 다른 원고에도 그대로 적용된다.
범용 구현은 `scripts/word_com_template.py` 의 `Typesetter` 와 보조 함수를 쓴다.

---

## 0. 기본 골격

- 공식 양식 DOCX 를 작업 사본으로 복사해 열고 `Content.Delete()` 로 본문만 비운다. 스타일·머리글·바닥글은 템플릿 것을 그대로 쓴다 (`open_word()`).
- 산출물은 `SaveAs2` 로 **새 이름**에 저장한다 (`save_new()`). 원본 템플릿과 기존 산출물을 열어 덮어쓰지 않는다.
- PDF 는 `ExportAsFixedFormat(path, 17)` (wdExportFormatPDF).
- 끝나면 `Close(False)` 후 `Quit()`. 저장은 `save_new()` 로만 한다 (`close_word()`).
- 스타일 이름은 템플릿의 이름을 그대로 쓴다. 없는 스타일을 적용하면 기본 단락으로 떨어지므로 경고를 남긴다.
- Word 인스턴스는 `DispatchEx` 로 띄운다 (§12).
- 선택: 자동 하이픈을 끈다 (`doc.AutoHyphenation = False`). 원천 TKIPS 조판기가 이 설정을 썼다. 저널 게재본의 하이픈 여부는 실측으로 확인한다.
- **충돌 항목**: 프로젝트 문서나 CLAUDE.md 에 "새 단락 삽입" 예시로 `Collapse(0) → InsertParagraphAfter() → MoveStart(1,1) → .Text` 가 적혀 있을 수 있다. 이 패턴은 아래 §1 의 흡수 사고를 낸 패턴이므로 쓰지 않고 §1 의 안전 패턴을 쓴다.

## 1. 단락 삽입: 흡수 사고

**금지 패턴 A** `rng.Collapse(0) → InsertParagraphAfter() → MoveStart(1,1) → rng.Text = …`
- 사고: 섹션 헤딩 앞에 넣은 본문이 헤딩에 흡수됐다. 다른 판에서는 블록 전체가 앞 절의 문단에 들어가, 3회 수술로 복원했다.
- 원인: Collapse(0) 위치가 다음 단락의 시작이라, 삽입 텍스트가 다음 단락의 서식과 경계에 섞인다.

**금지 패턴 B** `InsertParagraphAfter()` 로 빈 단락을 만든 뒤 `Paragraphs(i).Range.Text = …` 로 채우기.
- 사고: 절 제목과 본문이 한 단락으로 붙었다 ("…ToolsIndustrial test automation has…").

**안전 패턴**: 위치 P 에 `text + "\r"` 을 직접 넣는다. 단락 기호로 끝나므로 다음 단락이 보존된다.
```python
doc.Range(P, P).Text = text + "\r"        # P = 삽입 위치
```
- 본문 끝에 이어 쓸 때 P = `Content.End - 1` (마지막 단락 기호 바로 앞). `Typesetter.para()` 가 이 방식이다.
- 삽입 후에 스타일을 지정하고, 직접 서식은 그다음에 준다.

**검증**: 삽입 직후 앞뒤 단락의 인덱스·스타일·그림 수를 출력한다 (`Typesetter.dump_tail()`). 다음 헤딩 단락의 `InlineShapes.Count == 0` 인지 확인한다. 앵커 검색은 첫 매치가 의도한 섹션인지 확인한다. 같은 문구가 §2 에도 있어서 잘못된 곳에 앵커된 사고가 있었다.

**참조 drift**: `list(doc.Paragraphs)` 를 캐시하지 않는다. 삽입하면 인덱스가 밀린다. 필요할 때마다 텍스트 접두어로 다시 찾는다 (`find_para()`).

## 2. 런 서식: 번짐과 스타일 살해

두 함정은 둘 다 여러 판에 걸쳐 잠복했다.

1. **번짐(bleed)**: 색을 지정한 런 뒤에 삽입한 런이 직전 런의 직접 서식을 상속한다. 색이 문단 밖까지 번진다.
2. **스타일 살해**: 번짐을 막으려고 모든 런에 `Bold = 0`, `Color = Automatic` 을 명시 할당했더니, 스타일의 색과 볼드가 전부 검정 보통체로 덮였다. 스타일 정의는 멀쩡해서 스타일 검사로는 잡히지 않았고, 렌더 PDF 의 스팬을 게재본 기준값과 대조해야 드러났다 (8판본 잠복).

**정답 패턴**
- 런 삽입 직후 `r.Font.Reset()`. 이웃 직접 서식 상속을 끊는다.
- 문단 스타일을 적용한 **뒤**, 기록해 둔 런 범위에 **요청된 속성만** 준다.
  `if b: fr.Bold = -1` · `if i: fr.Italic = -1` · `if c is not None: fr.Color = c`
  요청하지 않은 속성은 건드리지 않는다. 스타일이 살아남는다.
- Word 의 색은 BGR 정수다. 파랑 `0xFF0000`, 빨강 `0x0000FF` (`word_color(r, g, b)`).
- 검증: `python scripts/pdf_page_audit.py <pdf> --spans "문구"` 로 글꼴·크기·굵기·기울임·색을 출력해 게재본과 대조한다.

## 3. 서식은 기록 시점에 건다

- 완성된 긴 문서에 `Find` 루프를 돌려 `Italic`·`Subscript` 를 거는 방식은 쓰지 않는다. 서식 한 건마다 Word 가 전체를 다시 쪼갠다.
  - 실측: 특화 표기 전환 206건을 이 방식으로 돌리자 CPU 97분을 쓰고도 끝나지 않았다. 기록 시점 방식으로 바꾸자 전체 조립이 8분에 끝났다.
  - `Options.Pagination = False` 나 초안 보기 전환으로는 해결되지 않았다.
- 방법: 텍스트를 찍을 때 런을 나눈다. 굵게(`**…**`) 처리와 같은 경로다.
  ```python
  sel.Font.Italic = True;    sel.TypeText(head); sel.Font.Italic = False
  sel.Font.Subscript = True; sel.TypeText(tail); sel.Font.Subscript = False
  ```
- 표 셀은 `cell.Range.Text = v` 로 한 번에 쓰므로 런 분할이 안 된다. 셀 시작 위치 + 문자 오프셋으로 `doc.Range(...)` 를 잡아 셀 단위로 서식을 준다. 셀 단위라 비용이 작다.
- 장시간 실행에서 `| tail` 로 파이프하지 않는다. tail 이 EOF 까지 버퍼링해서 멈춘 것을 모른 채 시간만 간다. `python -u` 로 스트리밍하고 로그 파일을 직접 읽는다.
- 멈춤 판정은 메모리가 아니라 WINWORD 프로세스의 CPU 시간을 두 번 재서 활동률로 한다.

## 4. 한글 줄바꿈: WordWrap 방향

- `ParagraphFormat.WordWrap = True` 는 **어절 단위**로 줄을 바꾼다. 기본값(False)은 글자 단위로 낱말을 쪼갠다. 이름과 효과가 반대라 추측으로는 맞힐 수 없다. 같은 폭의 셀 두 개에 WordWrap 만 다르게 주고 PDF 의 줄 좌표로 확정했다.
- **한계**: 공백 없는 낱말이 열보다 넓으면 여전히 쪼개진다 ("도메인" 이 22pt 열에서 "도/메/인"). 열 폭을 늘려야 한다 (§5).
- **반대 경우**: 2단 논문지 본문은 게재본이 줄 끝에서 낱말을 끊는다. 좁은 단에서 WordWrap=True 로 양쪽 정렬하면 낱말 사이가 크게 벌어진다. 그래서 2단 본문은 WordWrap=False, 제목은 True 로 둔다. 저널 양식을 실측해서 정한다 (`journal-formats.md`).

## 5. 표: 자동 맞춤과 열 폭

- `AutoFitBehavior(content)` 의 최소 열 폭은 끊을 수 없는 가장 긴 토큰으로 정해진다. 한글은 음절 단위로 어디서든 끊기므로 최소 폭이 한 글자가 된다. 짧은 한글 머리글 열이 한 글자 폭까지 눌려 "도 / 메 / 인" 처럼 세로로 쪼개졌다 (학위논문 표 34개 중 20개).
- 표를 만든 직후에는 `Columns(i).Width` 가 균등 분할 초기값이라 자동 맞춤 결과를 읽을 수 없다. 자동 맞춤 대신 열 폭을 계산해 직접 지정한다 (`plan_widths()`). 자동 맞춤 결과는 출발점으로만 쓴다.
- **배분 순서** (TIIS 조판기 v25 방식, `plan_widths()` 가 같은 순서를 쓴다):
  1. 열별 하한 = 가장 긴 낱말 × 글자당 pt + 여백. 머리글 하한은 따로 계산한다.
  2. 하한을 먼저 준다. 하한의 합이 전체 폭을 넘으면 비례 축소하고 `ok=False` 를 돌려준다. 이때는 글자 크기나 본문을 줄인다.
  3. 남는 폭을 나눈다. 희망 폭을 모두 줄 수 있으면 남는 폭을 희망 폭 비율로 더한다. 줄 수 없으면 하한 위에 추가 수요(희망 폭 − 하한) 비율로 나눈다.
  - 단순 비례 배분은 짧은 행 이름 열("LW" 등)을 세로 글자로 쪼갰다.
- **기증 열 상한**: 다른 열에서 폭을 뺏을 때 자기 폭의 28% 이내로 제한한다. 상한이 없으면 산문 열이 강탈당했다 (192pt → 47pt, 2행짜리 표가 세 쪽에 흩어졌다).
- **검증**: 머리글의 줄 수와 본문에서 가장 긴 셀의 줄 수를 **함께** 본다. 머리글만 보면 본문이 좁은 통로에 갇히는 회귀를 놓친다.
- **머리 행**: `Rows(1).HeadingFormat = True` (쪽을 넘으면 반복). 행은 `AllowBreakAcrossPages = False`. 머리 행과 첫 행은 `KeepWithNext` 로 묶어 고아 머리 행을 막는다.
- 표 전체 묶음(모든 행 KeepWithNext)은 빈칸을 만든다. 짧은 표 중 표시한 것만 통째로 묶는다 (`page-fitting.md`).
- 머리 행은 가운데 정렬, 본문 셀은 왼쪽 정렬이 기본이다.
- 연속된 두 표는 사이에 4pt 분리 단락을 넣어 병합을 막는다. 분리 단락은 **연속 표 사이에만** 만든다. 표 뒤의 일반 본문이 4pt 를 상속하면 안 되기 때문이다.

## 6. 수식(OMath): 단락 경계 삼킴

- (용어: `OMaths.Add` 는 수식 영역을 만들고, `BuildUp` 은 선형으로 적은 수식을 Word 수식 구조로 바꾸는 호출이다.)
- 넓은 다중행렬 수식에 `OMaths.Add` + `BuildUp` 을 하면 단락 경계가 소실되어, 다음 산문이 수식 단락에 합쳐지고 오른쪽 여백 밖으로 밀려 인쇄에서 잘린다. 추출 텍스트만 보면 블록 순서가 어긋나 착시가 난다. 해당 영역을 전폭으로 렌더링해서 눈으로 확인한다.
- **해법**: 번호 수식은 **테두리 없는 1×2 표** 로 격리한다. 셀1 = 수식(가운데), 셀2 = (번호)(오른쪽), `AllowBreakAcrossPages = False`. 셀 경계는 BuildUp 이 넘지 못하고, 넓은 수식은 셀 안에서 여러 줄로 접힌다. 부수 효과로 BuildUp 이 실패하던 수식도 변환에 성공했다 (12개 → 13개). `Typesetter.equation()` 이 이 구조다.
- 수식과 번호를 한 문단에 탭으로 넣으면 인라인 모드가 되어 좌측으로 쏠리고 임의로 줄이 바뀐다. 1×2 표로 나누면 수식이 단독 문단(디스플레이 모드)이 되어 가운데에 놓인다.
- **짝 없는 ASCII `|`** (예: `p(A | B)`)가 있으면 BuildUp 이 예외 없이 수식 전체를 선형 텍스트로 남긴다. 조건 기호는 유니코드 `∣`(U+2223)로 바꾼다. 짝이 맞는 `|…|` 는 정상 변환된다.
- **∑·∏ 피연산자**: 피연산자 앞에 UnicodeMath naryand `▒`(U+2592)를 넣어야 한계식이 위아래에 얹힌 2차원 구조로 빌드된다.
- 원고 소스는 `\mid` 같은 안전한 표기를 유지하고, 유니코드 변환은 조판 계층(`latex_clean` 류)에서 한다 (`source-pipeline.md`).

## 7. 머리말·바닥글

- PAGE 필드는 쪽 번호를 자동으로 넣는 Word 필드다. `Range.Text` 를 통째로 바꾸면 이 필드가 사라진다. 텍스트를 쓴 뒤 필드를 따로 `Fields.Add` 로 넣는다 (`header_with_page()`).
- 짝수·홀수 쪽을 다르게 쓰려면 `OddAndEvenPagesHeaderFooter = True`. 구역을 나눈 뒤 각 구역의 `LinkToPrevious = False` 로 끊고 나서 고친다.
- 머리말을 바꿀 때의 순서: 보존할 줄을 적어 둔다 → 텍스트를 쓴다 → PAGE 필드를 다시 넣는다 (`header_with_page()`). 바닥글도 같은 순서다.
- 첫 쪽 바닥글을 통째로 바꾸면 템플릿에 있던 DOI·ISSN 줄이 유실된다 (실제 사고). 바꾸기 전에 보존할 줄을 골라 다시 넣는다.
- 템플릿 잔재를 치환할 때(권호 표기, 연도 등)는 `Find.Execute` 가 일부를 건너뛸 수 있으므로 치환 뒤 결과를 확인한다 (§9).

## 8. 구역·단·그림 (2단 본문)

- 연속 구역 나누기(`wdSectionBreakContinuous`)를 넣으면 앞 구역의 2단이 Word 에 의해 균형 맞춰져 끝난다. 이 성질 때문에 잔여 높이를 추정할 때 "균형 잡힌 하단"을 따로 계산해야 한다 (`page-fitting.md` §4).
- 2단 문단에 `AddPicture` 를 하면 Word 가 단 폭(약 241pt)으로 자동 축소한다. 그림의 표시 폭은 조건부가 아니라 **무조건** 지정한다 (`Typesetter.picture()`).
- 텍스트박스 스토리에 `AddPicture` 를 직접 넣으면 Word 가 RPC 로 죽는다. 그림과 캡션을 블록으로 만든 뒤 `TextRange.FormattedText` 로 옮긴다.
- 그림 단락에 "정확히" 줄 간격을 주면 그림이 잘린다. 그림 단락은 단일 줄 간격(`LINE_SINGLE`)으로 지정한다.
- 그림 캡션이 그림과 떨어지지 않도록 그림 단락에 `KeepWithNext` 를 준다.
- 캡션 단락 자체는 `KeepTogether` 로 쪽 경계에서 쪼개지지 않게 한다 (원천 TIIS 조판기: 표 5 캡션이 쪽에서 갈린 실측). `Table`, `Algorithm` 캡션은 표와 붙도록 `KeepWithNext` 를 준다.
- 부동 프레임(wrap top-bottom)으로 그림을 띄우는 방식은 실패했다. 앵커 문단이 프레임을 못 담으면 앵커와 함께 다음 쪽으로 밀려 공백이 생겼고, 표와 제목이 많은 절에서는 유효한 앵커를 찾지 못했다. 1단 구역 + 지연 삽입이 최종 정답이다 (`page-fitting.md` §4).

## 9. Find/Replace 함정

- `Find.Replacement.Text` 는 255자 제한이 있다. 긴 텍스트는 단락 본문 범위를 직접 바꾼다 (`replace_para_text()`).
- `Find.Execute(Replace=2)` 는 같은 문자열이라도 문서에 따라 일부를 **소리 없이 건너뛴다**. StoryRanges 순회로도 해결되지 않았다. 신뢰할 수 있는 방법은 **단락을 역순으로 순회하면서 위치 기반으로 수술** 하는 것이다: `doc.Range(p.Range.Start + pos, …).Text = new`. 치환 후에는 원래 문자열이 남지 않았는지 다시 찾아 확인한다.
- 단락 전체의 `Range.Text` 를 바꾸면 단락 기호까지 지워 다음 단락과 합쳐진다. 단락 기호 앞까지만 범위를 잡는다.

## 10. Selection 기반 조립

- Selection 으로 긴 문서를 이어 붙이면 Selection 이 비결정적으로 문서 머리(위치 0)로 튈 수 있다. 표지 앞에 5장 분량이 삽입된 사고가 있었다. 재현은 안 됐고, 백그라운드 전환 같은 환경 요인이 의심됐다.
- **가드**: 기록 함수의 진입부마다 `Selection.EndKey(6)`(wdStory)로 "항상 본문 끝에 이어 붙인다"는 불변식을 강제한다 (`selection_to_end()`). 가능하면 `Range` 위치 기반 기록(`Typesetter`)을 쓴다.
- 릴리스 전에 PDF 1쪽 텍스트가 표지 제목으로 시작하는지 확인한다. 구조 검증은 이것으로 최소한 한다.

## 11. 학위논문 양식 조립 함정

1. **고정 줄 간격(Exactly)은 기준 글자 크기에만 맞는다.** 본문용 고정값을 Normal 에 걸면 20pt 이상 표지 제목의 줄바꿈 행이 겹치고, 이미지 문단은 잘린다. 크기가 다른 문단과 이미지 문단은 `LineSpacingRule = 0` 으로 다시 지정한다.
2. **`TablesOfFigures.Add` 의 키워드 인자는 오바인딩된다.** 캡션 스타일 수집이 무시되고 헤딩 기반 전체 목차가 들어가 쪽수가 폭증한다. 원시 필드를 쓴다: `doc.Fields.Add(rng, -1, 'TOC \h \z \t "스타일명,1"', False)`. 캡션 전용 단락 스타일을 만들어 캡션에 적용해 두면 목차가 자동으로 생긴다. 이 필드는 `doc.TablesOfContents` 에 잡히므로 갱신 루프에 함께 넣는다 (`add_caption_list_field()`).
3. **쪽번호 3구간**(표지 없음 / 앞부분 로마자 / 본문 아라비아): 구역을 나눈 뒤 각 바닥글을 `LinkToPrevious = False` 로 끊고 "- " + PAGE + " -" 를 넣는다. `PageNumbers.NumberStyle`(1 = 대문자 로마, 0 = 아라비아)과 `RestartNumberingAtSection = True` 를 지정한다. PAGE 필드는 구역의 번호 방식을 따른다.
4. 구역 나누기 직후에 페이지 나누기를 또 넣으면 빈 페이지가 생긴다.
5. **표 열 폭**: Word 기본은 균등 분할이라 내용이 많은 열이 좁게 감긴다. `AutoFitBehavior(1)` 후 `PreferredWidthType = 2`(퍼센트), `PreferredWidth = 100` 으로 두면 내용 비례 폭과 본문 전체 폭을 함께 얻는다.
6. 섹션 나누기를 넣은 뒤에는 첫 장의 렌더 결과에서 빈 페이지 여부를 확인한다.

## 12. 실행 관리

- Word COM 작업은 한 번에 하나만 돌린다. 병렬 에이전트가 같은 Word 를 건드리면 안 된다.
- `taskkill /f /im WINWORD.EXE` 는 사용자가 열어 둔 Word 창의 저장 안 된 내용까지 지운다. 실행 전에 사용자에게 확인한다 (`shell-pitfalls.md`).
- `Dispatch("Word.Application")` 은 이미 떠 있는 Word 에 붙는다. 그 상태에서 `Quit()` 를 부르면 사용자의 다른 문서까지 닫힌다. 그래서 `open_word()` 는 `DispatchEx` 로 새 인스턴스를 띄운다. 이 변경은 키트 환경에서 Word 로 실행 검증하지 못했으므로 첫 실행은 scratch 에서 확인한다.
