# 웹 한글 편집기 자동화 함정

정식 한글이 없을 때 브라우저의 웹 한글 편집기(한컴독스)를 자동화해 HWP 원고를 고치는 경로의 함정이다.
화면 좌표와 문서 주소는 세션마다 달라서 적지 않았다. 원리만 남긴다.
가능하면 정식 한글을 쓰고, 이 경로는 대안으로만 쓴다. 결과는 반드시 PDF 와 텍스트 추출로 검증한다.

---

## 1. 키 입력

- **연속 키 드랍**: 한 번의 배치 안에서 방향키나 Return 을 연달아 보내면 일부가 씹힌다. `repeat` 옵션도 한 번만 적용되는 경우가 있었다. 키 사이마다 0.4초 대기를 넣는다.
- **End 는 문단 끝이 아니라 표시줄 끝이다.** 여러 표시줄로 된 문단에서 End 후 Delete 를 하면 다음 표시줄의 본문 글자가 지워진다 (참고문헌 항목의 글자가 지워진 사고). 문단 끝을 확실히 잡을 방법이 없으니, End 는 마지막 표시줄에서만 쓴다.
- **유니코드 이스케이프 오타**: 한글을 `\u` 이스케이프로 넣으면 비슷한 글자로 잘못 들어간다 (예: "곳" 을 "곧" 으로). 한글은 원문 그대로 넣고, 넣은 뒤 찾아 바꾸기로 검수한다.

## 2. 선택과 교체

- **shift+클릭으로 잡은 선택의 끝점을 믿지 않는다.** 클릭 좌표와 실제 선택 끝이 어긋나서 과삭제가 두 번 났다. Delete 전에 하이라이트의 양 끝을 줌 화면으로 확인한다.
- **문단 통째 교체**
  1. 문단 첫 줄을 클릭하고 Home 을 누른다.
  2. shift+Down 을 (표시줄 수 − 1) 번 누른다. 키 사이마다 대기한다.
  3. shift+End 로 마지막 표시줄 끝까지 잡는다.
  4. 상태 표시줄의 "선택 글자 수 / 전체" 가 원문 글자 수(들여쓰기 공백 포함)와 맞는지 확인한다.
  5. 새 문단을 입력한다.
- `shift+ctrl+Down` 은 문단 끝까지 잡지만 **문단 기호까지 포함**하므로, 문단 시작에서 입력하면 다음 문단과 합쳐진다. 문단 중간에서 찌꺼기를 끝까지 지울 때만 쓴다.
- **쪽·단 경계를 넘는 문단은 한 번에 잡지 않는다.** 경계에서 선택이 그림과 표까지 튀어 1,188자가 과선택된 사고가 있었다. 앞부분만 선택해 새 문단을 입력하고, 남은 옛 문장을 문단 끝까지 잡아 지운다.
- 제목 문단을 트리플클릭한 뒤 입력하면 문단 기호까지 지워 다음 문단이 끌려 올라온다. 한 셀 안의 여러 줄(저자, 소속, 이메일)은 한 문단이라 트리플클릭이 전부 선택한다. 줄 앞을 클릭하고 Home 을 누른 뒤 입력하고 Return 으로 나눈다.
- 헤딩 교체는 클릭 → Home → shift+End → 입력 순서가 굵기를 유지했다. 트리플클릭보다 안전하다.

## 3. 서식

- **트리플클릭 교체 뒤 서식이 상속되지 않는다.** 제목을 트리플클릭해서 입력하면 본문체(가는 글씨)로 들어오는 경우가 있다. 교체 뒤 트리플클릭으로 다시 잡고 굵게를 준다. 반대로 제목 문단 시작에서 입력한 캡션이 굵게 들어오기도 한다. 결과는 항상 줌으로 확인한다.
- **굵게 단축키**: ctrl+b 가 먹지 않았다. 툴바의 굵게 버튼을 쓴다.
- **가운데 정렬 단축키 ctrl+shift+c** 는 동작했다. 툴바 정렬 버튼은 개체가 선택된 상태에서 무효였다.
- **문단 부호 보기**: 보기 메뉴에서 문단 부호를 켠다 (단축키 Alt+G 다음 T). 빈 문단을 진단하거나 문서 끝을 정리할 때 필요하다.
- **문서 끝 빈 문단**: 클릭 스냅 때문에 잘 지워지지 않는다. y 차이가 큰 shift+클릭 선택이 그나마 통했다.
- **참고문헌 규정**: 항목을 선택한 뒤 글자 크기 필드에 8, 줄 간격 필드에 100 을 입력하고 Return 을 누른다. 쪽수를 줄이는 결정타였다.

## 4. 찾기와 바꾸기

- 찾기 대화상자(ctrl+f)와 찾아 바꾸기 대화상자(ctrl+h)는 대체로 잘 동작한다.
- **"다음 찾기"는 캐럿을 옮기지 않는 경우가 있었다.** 위치를 잡을 때는 찾기 뒤에 클릭과 Home 으로 확정한다.
- **찾아 바꾸기 "문서 전체" + "모두 바꾸기"는 확실히 동작했다.** 표 셀 안의 글도 바뀌고, 바꾼 횟수가 표시된다. 오타 정정과 제목 교체에 쓴다.
- **마커 방식**: 본문에 `[[그림1]]` 같은 마커를 넣어 두고, 찾아서 지운 뒤 그 자리에 그림이나 표를 넣는다. 좌표를 추적하지 않아도 되어 안전하다.
- 찾기 뒤 닫기를 하면 선택이 유지된다. "찾기 → 닫기 → 툴바 굵게" 가 제목 굵게의 정석이다.

## 5. 표

- 표를 만들 때 칸 개수를 입력한 뒤 **Tab 으로 값을 확정해야** 만들기가 먹는다. Tab 을 하지 않으면 표가 생기지 않는다.
- "글자처럼 취급" 옵션을 켠다.
- 셀 채우기는 입력 + Tab 을 반복하고, 사이마다 0.3초 대기하는 방식이 안정적이었다.

## 6. 그림

- 그림 넣기 대화상자에서 파일 입력 요소를 찾아 업로드한 뒤 "넣기"를 누른다. 파일 업로드 인자는 배열로 준다.
- **크기가 큰 PNG(약 2.7MB)는 조용히 실패한다.** 폭 1,000px, 100KB 안팎으로 줄이면 단 폭에 자동으로 맞춰 들어간다.
- "글자처럼 취급"이 기본으로 켜진다. 크기는 개체 속성에서 mm 로 직접 입력한다. 비율이 자동으로 연동되지 않으므로 높이도 계산해서 넣는다.

## 7. 저장과 검증

- 제목 줄을 눌러 이름을 바꾸면 파일 이름이 바뀐다.
- 저장은 ctrl+s 로 자동 저장을 확정한다. 두 탭을 동시에 편집하는 상태에서도 반영되었다.
- 내보내기는 HWP 와 PDF 로 한다. PDF 로 쪽수를 확인하고, HWP 는 텍스트 추출 도구로 본문을 검증한다.
- 문서 직접 주소로 열면 "주소가 올바르지 않다"는 오류가 나는 경우가 있었다. 홈 화면의 최근 문서 카드를 눌러 편집기 탭을 열었다.
- 사용자 탭과 자동화 탭에서 같은 문서를 동시에 열어도 편집 내용이 반영되었다 (탭 제목에 "편집 (2)" 가 붙는다).
