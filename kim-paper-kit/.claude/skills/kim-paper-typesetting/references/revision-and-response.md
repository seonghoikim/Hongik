# 리비전 원고와 답변서 조판

심사 후 수정본(리비전 원고)을 만들 때의 표시 규칙과, 답변서를 첫 구역에 붙이는 구조를 정리한다.
이 키트 문서에는 심사평의 원문을 옮기지 않는다. 여기서는 조판 형식만 다룬다. 실제 답변서의 코멘트 포함 여부는 저널 지침과 저자가 정한다.

---

## 1. 수정 표시 (원고 소스)

| 원고 표기 | 조판 결과 | 근거 |
|-----------|-----------|------|
| `{+ 수정 문장 +}` | 파랑 굵게 | 편집자 지시: 수정 부분을 파랑으로 표시 |
| 수정 문장 안의 인용 `[N]` | 빨강 유지 | 인용 색 규정이 우선 |
| `<!-- REV-TABLE -->` 다음 표 | 표 전체 파랑 굵게 | 표 전체가 바뀐 경우 |
| 셀 안의 `{+ … +}` | 그 셀만 파랑 굵게 | 셀 하나만 바뀐 경우 |
| `{+$$ … $$+}` | 수식 파랑 | 수정된 수식 |
| 수정된 제목 | 파랑 색만 | 굵기는 스타일에 맡긴다 |

- `{+` 와 `+}` 의 개수가 같은지 `check_source.py` 로 확인한다. 한쪽만 남으면 그 뒤 문단 전체가 파랑이 된다.
- 수정 표시는 소스에서만 다룬다. 조판기는 표시를 색으로 바꾸고, 소스 파일에서 표시를 지우지 않는다.

## 2. 공저자 입력 자리

- `‹TBD: …›` 는 노란 형광으로 강조된다. 공저자가 채워야 할 정보(약력 확인, 사진, 날짜 등)에 쓴다.
- 제출 전에 모두 확정하고, `check_source.py` 의 TBD 경고가 0 이 되도록 한다.
- 날짜처럼 아직 정해지지 않은 항목은 em dash(`—`) 자리표시로 두고, 확정되면 바꾼다. 예: 접수일만 확정하고 수정·채택·출판일은 `—` 로 둔다.

## 3. 답변서 구역 구조

리비전 PDF 는 **답변서 + 수정된 원고** 를 한 파일로 낸다. 구조는 다음과 같다.

1. **첫 구역 = 답변서.** `response.md` 를 조판한다.
2. **구역 나누기(다음 쪽)** 후 원고를 시작한다. 원고의 쪽 번호는 **1부터 다시 센다** (`RestartNumberingAtSection`).
3. **머리글·바닥글 분리**: 원고 구역의 머리글·바닥글을 답변서 구역과 끊는다 (`LinkToPrevious = False`). 그 뒤 답변서 구역의 머리글·바닥글은 비운다. 원고의 러닝 헤드가 답변서 쪽에 나오지 않게 하려는 것이다.
4. **쪽수 집계**: 답변서 쪽수 = 원고 구역 첫 쪽의 절대 쪽 번호 − 1. 원고 쪽수 = 전체 쪽수 − 답변서 쪽수. 저널의 쪽수 규정은 원고 쪽수 기준인지 확인한다.
5. **첫 쪽 바닥글 보존**: 원고 구역의 첫 쪽 바닥글(사사, DOI·ISSN 줄)은 답변서 구역과 별개로 유지한다 (`word-com-rules.md` §7).

## 4. 답변서 서식 (형식만)

답변서는 다음 형식으로 조판했다. 글꼴은 Times New Roman 11pt, 양쪽 정렬이다.

| 요소 | 서식 |
|------|------|
| 답변서 제목 | 15pt 굵게, 가운데 |
| 절 제목 (예: 편집자 지시, 심사자 번호) | 12.5pt 굵게, 왼쪽, 위 12pt · 아래 6pt |
| 심사 코멘트 라벨 `Comment I.` | 굵게 |
| 심사 코멘트 본문 | 이탤릭, 회색(#555555). 답변서에 넣을 코멘트는 저널 지침을 따른다. 이 키트 문서에는 심사평 원문을 싣지 않는다. |
| 응답 라벨 `Response.` | 굵게 |
| 수정 위치 안내 `Changes in the manuscript:` | 파랑 (수정된 쪽·절을 명시) |
| 목록 항목 (`- `) | 왼쪽 들여쓰기 14pt, 아래 간격 2pt, 앞에 `•` |
| 코멘트 사이 간격 | 위 10pt |

- 응답 번호는 편집자 지시 번호와 맞춘다. 예: 편집자 지시 4번에 대한 답은 답변서의 "4" 항목에 둔다.
- 답변 본문에는 "수정 위치"를 쪽과 절로 적는다. 쪽 번호는 조판이 끝난 뒤 렌더 PDF 에서 확인하고 적는다. 조판 전에 쪽을 추정해 적지 않는다.

## 5. 리비전 점검 체크리스트

- [ ] 모든 수정 문장이 `{+ +}` 로 표시되었는지 (수정 누락 = 심사자 검토 실패)
- [ ] `{+` 와 `+}` 개수가 같은지 (`check_source.py`)
- [ ] 인용 `[N]` 이 수정 문장 안에서도 빨강인지 (렌더 PDF 에서 `--spans` 로 확인)
- [ ] 답변서의 수정 위치 쪽 번호가 렌더된 원고의 실제 쪽과 맞는지
- [ ] 답변서 구역에 원고의 머리글·바닥글이 나오지 않는지
- [ ] 원고 쪽 번호가 1에서 시작하는지
- [ ] TBD 자리표시가 모두 확정되었는지
- [ ] 새 파일 이름으로 저장했는지 (이전 리비전 판을 덮어쓰지 않는다)
