# 원고 소스 → 조판기 구조

원고는 Markdown 으로 쓰고, 조판기가 그것을 읽어 DOCX 로 만든다. 이 문서는 소스의 표기 규칙과 조판기의 처리 순서를 정리한다.
토큰 이름은 예시다. 조판기를 새로 만들면 같은 원리의 토큰을 골라 쓰되, 한 프로젝트 안에서는 하나의 규칙으로 고정한다.

---

## 1. 원칙: 소스는 안전한 평문, 변환은 조판 계층에서

- 소스(.md)는 사람이 쓰는 원본이다. 조판기는 소스를 **읽기만** 한다. 조판 중에 소스를 고치지 않는다.
- 조판 전용 변환(LaTeX → 선형 표기, 색, 아래첨자 표기, 리비전 색)은 조판 계층에서 한다. 소스에는 안전한 표기만 둔다.
  - 예: 식별자 표기 `L_fas` 는 소스에 평문으로 두고, 조판 계층에서 이탤릭 첫 글자 + 아래첨자 런으로 바꾼다.
  - **데이터 키(JSON·JS 키, 코드 식별자)는 절대 치환하지 않는다.** 표시 마크업만 바꾼다. 데이터 키를 치환하면 데이터 정합이 깨진다.
- 소스 표기가 조판 계층 변환과 충돌하는 예: 표 셀 안의 수식에서 리터럴 `|` 는 셀 구분자로 읽힌다. 소스는 `\mid` 를 유지하고, `\mid → |` 변환은 조판 계층에서 한다. 행의 파이프 수는 `check_source.py` 로 검사한다.

## 2. 파일 분할 (권장)

조판기가 순서대로 읽을 수 있도록 원고를 나눈다. 예시 구성:

| 파일 | 내용 |
|------|------|
| `sec1_front.md` | 제목, 저자 정보, Abstract, Keywords, 본문 1절 시작 전까지 |
| `sec2_*.md` ~ `sec6_*.md` | 본문 절 (관련 연구, 방법, 사례, 평가, 결론 등) |
| `refs.md` | 참고문헌 (`[N] …` 한 항목 한 줄) |
| `response.md` | 리비전 답변서 (리비전 원고에만) |

- 파일 경계에서 헤딩 깊이 규칙이 끊기지 않도록 한다. 조판기는 파일마다 `process_lines()` 를 호출한다.
- 조판기 호출 순서: 답변서(있으면) → 구역 나누기 → 전면부 → 본문 파일 순서 → 참고문헌 → 저자 약력 → 머리글·바닥글 → 끝 단락 정리 → 저장.

## 3. 헤딩 규칙

조판기는 헤딩 기호와 번호 형식을 보고 스타일을 정한다 (TIIS 조판기의 실측 규칙):

| 원고 표기 | 조판 |
|-----------|------|
| `# 제목` (전면부 첫 줄) | 논문 제목 스타일 |
| `## Abstract`, `## Keywords` | 초록 제목 / 키워드 블록 (전면부 특수 처리) |
| `## 1. Introduction` (N. 형식) | 절 스타일 (heading1) |
| `### 2.1 …` (N.M 형식) | 소절 스타일 (heading2) |
| `References`, `Acknowledgement`, `Author Profile`, `Appendix` | 절 스타일 (heading1) |
| 그 밖의 헤딩 | **조판에서 건너뛴다** (파일 보조 제목) |

- 주의: 파일 안의 보조 제목은 본문에 나오지 않는다. 본문에 나와야 하는 제목은 위 형식 중 하나로 쓴다.
- 저널이 소절 번호 체계를 제한하면 원고도 그에 맞춘다. 예: 논문지는 `1.` → `1.1` → `1)` → `a)` 4단계까지만 허용하고 `3.1.1` 은 쓰지 않는다. 학회지는 서론에 소절을 두지 않는 편을 교수님이 선호했다 (`journal-formats.md`).

## 4. 인라인 표기

| 원고 | 조판 |
|------|------|
| `**굵게**` | 굵게 |
| `*기울임*` | 기울임. 굵게 안의 기울임 중첩을 지원한다 (`**… *k* …**`) |
| `` `코드` `` | 백틱 제거 후 평문 (코드 글꼴은 쓰지 않는다. 코드 블록은 §6) |
| `$수식$` | 조판 계층에서 선형 표기로 변환 (§5) |
| `[N]`, `[N]–[M]`, `[N][M]` | 인용. 색 규정에 따라 빨강 (§7) |
| `Fig. N`, `Figs. N–M`, `Table N`, `Algorithm N`, `Fig. N(a)` | 본문 참조. 색 규정에 따라 파랑 + 굵게 (§7) |
| `‹TBD: …›` | 공저자 입력 자리. 노란 형광 강조. 제출 전 확정 (§8) |
| `<!-- … -->` | 조판 시 무시 (작성자 메모) |
| `---` | 조판 시 무시 (구분선) |

## 5. 수식

- 한 줄 수식: `$$ … \tag{N} $$` (번호는 `\tag{N}`).
- 여러 줄 블록: 여는 `$$` 줄과 닫는 `$$` 줄 사이에 여러 줄을 쓴다. 번호 태그는 블록 안에서 찾는다. (수식 구분 기호의 개수는 항상 짝이 맞아야 한다. `check_source.py` 가 짝이 안 맞으면 오류로 잡는다.)
- 조판은 수식을 **1×2 무테두리 표**로 격리한다 (`word-com-rules.md` §6). 번호는 오른쪽 셀이다.
- LaTeX → 선형 표기 변환(조판 계층 `latex_clean` 류)의 예:
  - 그리스 문자와 `\mathbb{R}`, `\cdot`, `\times`, `\in` 은 유니코드로 바꾼다.
  - `\text{…}`, `\mathrm{…}` 은 내용만 남긴다. `\left`, `\right` 는 제거한다.
  - `_{…}`, `^{…}` 는 OMath 선형 입력 형식 `_(…)`, `^(…)` 로 바꾼다.
  - `\begin{bmatrix} a & b \\ c & d \end{bmatrix}` 는 OMath 행렬 `(■(a&b@c&d))` 로 바꾼다.
  - 짝 없는 `|` 는 유니코드 `∣` 로 바꾼다. `\mid` 는 조판 계층에서 `|` 로 바꾸되, OMath 에서 짝 없는 `|` 가 문제가 되면 `∣` 를 쓴다.
- 변환 결과는 반드시 렌더로 확인한다. BuildUp 이 실패하면 이탤릭 텍스트로 떨어진다. 그 수식은 한 번 더 확인한다.

## 6. 그림, 표, 코드 블록

### 그림
- 본문의 그림 자리는 한 줄 토큰으로 쓴다: `[[FIGURE n]]` (TKIPS 조판기는 `[[FIG n]]` 를 쓴다. 프로젝트마다 하나로 고정한다).
- 바로 다음 글줄에 캡션을 쓴다: `**Fig. n.** 캡션 설명.` 캡션 설명은 마침표로 끝낸다. IJIBC 처럼 접두가 `Figure n.` 이면 그 형식으로 쓰고, 조판기의 캡션 인식 정규식도 같은 접두를 받도록 고친다 (원천 TIIS 조판기는 `Fig. n.` 만 인식했다).
- 그림 파일 경로는 토큰 번호와 파일의 매핑 표(`FIGMAP` 같은 메타 블록)로 관리한다. 번호를 파일 이름에 섞지 않는다.
- 같은 번호의 토큰은 한 번만 쓴다 (`check_source.py` 가 중복을 잡는다).

### 표
- 파이프 표를 쓴다. 첫 행은 머리글이다. 머리글 셀은 조판에서 굵게 처리된다.
- 셀 굵게: `**…**`. 리비전 셀: `{+…+}` (§8).
- 셀 안 수식은 `\mid` 를 유지한다. 리터럴 `|` 를 쓰면 행이 쪼개져 빈 열이 생긴다 (`check_source.py` 가 잡는다).
- 모든 행의 파이프 수를 같게 맞춘다. 한 행만 다르면 표 전체에 빈 열이 붙는다.
- 표 묶음 주석: 짧은 표를 쪽 경계에서 통째로 묶을 때 표 앞에 `<!-- KEEP-TABLE -->` 를 쓴다. 전체 리비전 표는 `<!-- REV-TABLE -->` 를 쓴다 (§8).
- 표 제목: 표 위에 `**Table n.** 제목` (저널이 표 제목을 표 위에 두는 경우).

### 코드 블록
- 펜스(```` ``` ````) 안의 줄은 코드 글꼴(Consolas 8pt), 왼쪽 들여쓰기 0.6cm로 조판한다. 설명용 짧은 코드에만 쓴다.

## 7. 색 규정 (저널 규정이 요구하는 경우)

조판 계층에서 자동으로 색을 입힌다. 소스에는 색 표기를 넣지 않는다.

| 대상 | 색 | 굵기 |
|------|----|------|
| 인용 `[N]`, `[N]–[M]` | 빨강 | 굵지 않음 |
| 본문 그림·표 참조 `Fig.`, `Table`, `Algorithm` | 파랑 | 굵게 |
| 캡션 접두 `Fig. N.` (게재본 실측) | 파랑 | 굵게 |
| 캡션 설명 | 검정 | 보통 |

- 인용 색은 리비전 표시 안에서도 유지한다. 리비전 표시의 파랑이 인용의 빨강을 덮지 않는다.
- 색이 적용된 런은 word-com-rules.md §2 의 요청 속성 규칙을 따른다 (스타일의 색과 볼드를 죽이지 않는다).
- 색 규정이 없는 저널에서는 이 표를 적용하지 않는다. 기본은 검정이다.

## 8. 리비전 표시

- 수정 문장: `{+ … +}` → 파랑 굵게. 인용 `[N]` 은 빨강을 유지한다.
- 수정 표 전체: 표 앞 `<!-- REV-TABLE -->` → 표 전체 파랑 굵게.
- 수정 수식: `{+$$ … $$+}` → 파랑.
- 수정 제목: 파랑 색만 준다. 굵기는 스타일에 맡긴다 (직접 서식으로 굵기를 덮지 않는다).
- `{+` 와 `+}` 의 개수가 같은지 `check_source.py` 로 확인한다.
- 공저자 입력 자리 `‹TBD: …›` 는 노란 형광으로 강조된다. 제출 전 모두 확정하고, `check_source.py` 의 경고가 0 이 될 때까지 지운다.

## 9. 메타 블록 (표제 정보)

표제 정보(제목·저자·초록·키워드·머리글 문자열)는 본문 소스와 분리된 메타 블록에 둘 수 있다. 예시:

```
@TITLE_EN: <영문 제목>
@AUTHORS_EN: <저자 목록>
@ABSTRACT: <초록 한 단락>
@KEYWORDS_EN: <키워드, 쉼표 구분>
@RUNNING_ODD: <홀수 쪽 머리글>
@RUNNING_EVEN: <짝수 쪽 머리글>
@FOOTNOTE: <첫 쪽 각주 한 줄>        (여러 줄 가능)
@BIO: <이름> | <사진 파일>          (다음 줄부터 약력 항목)
```

- 메타 블록은 조판 전에 파싱해 제거한다. 조판기는 `@KEY:` 로 시작하는 줄만 메타로 본다.
- 저자 약력은 저널 규정상 필수일 수 있다. 누락하면 심사에서 반려될 위험이 있으므로 저자 전원분을 확인한다.

## 10. 조판기 처리 순서 (권장 골격)

```
1. check_source.py 로 소스 점검 (오류 0 이 될 때까지 소스를 고친다)
2. 공식 템플릿 사본 열기, 본문 비우기
3. (리비전) 답변서 구역 조판 → 다음 쪽 구역 나누기 → 쪽 번호 1부터
4. 전면부: 제목, 저자, 소속, 접수일 줄, Abstract, Keywords
5. 본문 파일 순서대로:
     헤딩 → 스타일
     [[FIGURE n]] → 지연 배치 대상 (page-fitting.md §4)
     표 → 열 폭 계산 후 기록
     수식 → 1×2 표
     캡션 → 캡션 스타일
     본문 단락 → 인라인 표기 + 색 규정
     보류한 그림은 조건이 맞을 때 삽입, 쪽 끝에서 강제 배출
6. 참고문헌 (DOI 가 있으면 링크를 넣는다. 저널이 링크를 요구하지 않으면 생략한다)
7. 저자 약력 (표 한 줄에 사진과 텍스트)
8. 머리글·바닥글 (PAGE 필드 보존, 첫 쪽 바닥글의 보호 줄 유지)
9. 문서 끝 단락 정리 (page-fitting.md §3)
10. save_new() 로 새 이름 저장 + PDF
11. pdf_page_audit.py 로 쪽별 빈칸 측정, --spans 로 색·볼드 대조
12. 렌더 PNG 를 눈으로 확인 (잘림, 캡션 분리, 표 분할 위치, 수식 잘림)
```

## 11. 점검 명령

```bash
python "<KIT>/scripts/check_source.py" sec1_front.md sec2_related.md   # 소스 점검
python "<KIT>/scripts/pdf_page_audit.py" trial.pdf --flag 100           # 쪽별 빈칸
python "<KIT>/scripts/pdf_page_audit.py" trial.pdf --spans "Abstract"   # 글꼴·색 실측
```
`<KIT>` 는 키트 루트의 절대 경로로 바꿔 쓴다.
