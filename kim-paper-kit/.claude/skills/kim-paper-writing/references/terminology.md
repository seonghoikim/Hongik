# 용어 확정 절차

## 1. 원칙

- 용어는 의미 층위별로 정하고, 영어 대응은 한국어와 영어 사전을 둘 다 대조해서 정한다.
- 번역 용어를 한쪽 사전으로만 확인하지 않는다. 한국어 낱말의 뜻풀이와 영어 낱말의 제1 어의를 나란히 본다.
- 확정은 교수님(또는 연구 책임자)이 한다. 저자가 임의로 확정해서 전체 문서에 퍼뜨리지 않는다.
- 확정 후에는 전역 치환하고, 용어표에 등재한다.

Why: 한국어 '행위'를 영어 behavior로 옮겨 쓰다가 어색함이 생겼다. 영어 사전의 제1 어의는 "처신하는 방식"이라 낱개 단위를 가리키지 않았다. 처음 낸 권고("behavior를 가산명사로 쓰면 된다")는 한국어 뜻풀이를 대조하지 않은 채 나온 것이라 철회했다. 이 실수를 막으려면 두 사전을 같이 본다.

## 2. 확정 절차 (7단계, 2026-08 용어확정안 사례에서 정리)

1. 문제 제기: 교수님 지적 또는 자체 검토로 용어가 어색한 이유를 찾는다.
2. 사전 대조: 한국어 사전의 뜻풀이(예: 행위, 행동, 행태, 동작)와 영어 사전의 제1 어의를 비교한다. 분야 관례(테스팅, 가상환경 문헌, 심리학 등)도 확인한다.
3. 층위 분리: 묶음, 단위, 내부 실행, 물리 움직임처럼 같은 말을 여러 층위로 나눈다.
4. 후보 제시: 2~3안과 권고안을 제시한다. 각 안의 장단점(짧음, 소유자 표시, 타 분야 약어와의 충돌)을 쓴다.
5. 확정 요청: 교수님께 "하나만 정해 달라"고 요청한다. 선택지는 번호로 붙인다.
6. 전역 치환: 확정 용어를 모든 문서에 적용하고, 문서별 수정량 표를 만든다.
7. 용어표 등재와 기록: 용어, 정의, 영문, 금지어를 용어표에 적고, 변경 이력을 남긴다.

## 3. 예시: 행위 단위 용어 (설명용)

문제: 단위를 'behavior unit'으로 불렀지만, 교수님은 어색하다고 하셨다.

사전 대조 결과:
| 낱말 | 한국어 뜻풀이 | 영어 대응 | 함축 |
|---|---|---|---|
| 행위 | 사람이 의지를 가지고 하는 짓 | action (낱개) | 낱개, 의도적 |
| 행동 | 몸을 움직여 동작을 하거나 일을 함 | behavior 또는 movement | 넓음 |
| 행태 | 행동하는 양상, 부정적 함의 | behavior(양상) | 학술 용어로 부적합 |
| 동작 | 몸이나 손발을 움직임 | motion, movement | 물리적 움직임 |

층위 분리 결과 (예):
| 층위 | 영어 | 한국어 | 가리키는 것 |
|---|---|---|---|
| 묶음 | behavior | 행동 | 여러 행위가 이어진 덩어리, 공유 부분경로 |
| 단위 | action | 행위 | 아바타가 객체를 한 번 건드리는 것. 트리거 1개, 결과 1개 |
| 내부 실행 | function, method | 함수, 메소드 | 행위로 엔진이 실제 수행하는 것 |
| 물리 | movement, motion | 동작 | 아바타의 이동과 애니메이션 |

확정 후보:
- 단위 이름: Avatar Action Unit (AAU), 한국어 "아바타 행위 단위". 소유자(아바타)를 붙여 "누구의 단위인가"에 답한다. 컴퓨터 비전의 FACS Action Unit과 이름이 겹치는 문제도 피한다.
- 대체 후보: Test Avatar Action Unit (TAAU), Action Unit (AU). AU는 짧지만 타 분야와 충돌한다.
- 함께 바뀌는 것: Behavior Matrix → Action Matrix. 이것은 개명이 아니라 원 용어로 되돌리는 복원이다. 박사논문의 원 용어가 Action Matrix였기 때문이다.
- behavior는 폐기하지 않고 "액션들의 공통 덩어리"를 가리키는 데 쓴다. 예: reusable behavior (공유 부분경로).

교수님이 확정한 이름 하나만 본문에 쓴다. 확정 전까지는 후보를 본문에 쓰지 않는다. 이 예시에서는 9월 발표 자료부터 TAAU 표기가 쓰였다. 확정 기록은 원천에서 확인한다.

## 4. 소유자 표기

- "누구의 단위인가"라는 질문이 나오면 접두어를 붙인다: Avatar, Test, User 등.
- 접두어를 붙일 때 타 분야 약어와 충돌하는지 검색한다.
- 약어는 첫 등장에 풀네임을 쓴다.

## 5. 사용 규칙

- 첫 등장: 정의 + 영문 병기. 이후에는 약어든 풀네임이든 하나로 통일한다.
- 같은 대상을 여러 이름으로 부르지 않는다. 이름이 바뀌면 전역 치환한다.
- 관련 쌍을 함께 쓴다: 예 "action matrix and use case dialog map"처럼 짝을 맞추면 심사자가 체계를 읽는다.
- 교수님 박사논문 용어를 확장할 때는 용어 구조를 보존하고 도메인 부분만 바꾼다. 예: action unit → behavior unit처럼 unit 개념을 유지한다. 이때 바꾼 이유를 한 번 밝힌다. 단, 이 예의 'behavior unit'은 '행위'의 뜻풀이와 맞지 않아, '행위'의 대응어가 action임이 확인된 뒤 action 계열(AAU·TAAU)로 되돌렸다(§1). 구조를 보존해도 번역어는 §1의 사전 대조를 거친다.

## 6. 최적화와 비최적화 명명

- 상위 범주: 비최적화 알고리즘 (Non-optimization Algorithm).
- 그 안에서 새로 제안한 기법은 구체 이름으로 쓴다. 예: Maximal Spanning Tree.
- 첫 등장에 상위 범주와 기법을 함께 쓰고, 이후에는 "비최적화 알고리즘"과 기법명으로 나누어 쓴다.
- 'Dijkstra의 역' 같은 비교 프레임을 본문 제목에 쓰지 않는다. 최적화 대 비최적화로 쓴다.

## 7. 금칙어와 공식 용어 변경

- 교수님이 특정 용어를 쓰지 말라고 하면 금칙어 목록에 넣고, 전 문서에서 찾아 바꾼다.
- 예: 옛 용어를 정부·산업계 공식 용어로 바꾸라는 지시. 전역 검색으로 치환하고, 영문은 문맥에 따라 다른 번역을 쓴다.
- 인용 문헌 제목 안에 있는 원저자 표기는 그대로 둔다. 원저자 제목을 임의로 바꾸지 않는다.

## 8. 정확성이 필요한 용어 쌍

| 쓰지 말 것 | 쓸 것 | 이유 |
|---|---|---|
| maximum spanning tree (가중치 합 최대) | maximal spanning tree (더 가지를 칠 수 없는 트리) | 알고리즘이 가중치를 최대화하지 않는다 |
| 정확(exact) + 몬테카를로(샘플링) | 전수 열거 또는 샘플링 중 하나 | 두 방법은 양립하지 않는다 |
| 시뮬레이션이 맞다 (검증 대상이 시뮬레이터일 때) | 시뮬레이터 검증 | "시뮬레이션이 맞다"로 읽힌다 |
| 구매 펑션 vs 클릭 펑션 | 단위는 검증 가능한 상태 변화를 남기는 의미 행위 | 입도 규칙을 명시 |

## 9. 전역 치환 절차

1. 확정안 문서를 먼저 만든다. 대상 용어, 치환 후 용어, 금칙어를 적는다.
2. 치환 대상을 검색한다. 한 번에 바꾸지 말고 검색 결과 수를 먼저 센다.
3. 식별자는 건드리지 않는다. 데이터 키, 코드 ID, JSON 키는 그대로 두고 표시 텍스트만 바꾼다. 소스 식별자를 바꾸면 데이터 정합이 깨진다.
4. 확정 수치와 인용 제목은 치환하지 않는다.
5. 치환 후 잔존 검색으로 옛 용어가 남았는지 확인한다.
6. 문서별 수정량 표(문서, 수정 내용, 규모)를 남긴다.
7. 교수님 직접 교정 문장은 건드리지 않는다.

두 이름을 맞바꿀 때(A↔B)는 중간 토큰을 거쳐 한 번에 치환한다. 순차 치환(A→B를 한 뒤 B→A를 하면)은 처음 바꾼 것을 되돌려 망가뜨린다. 치환 전후 검색 결과 수를 대조한다.

예시 수정량 표:
| 문서 | 수정 내용 | 규모 |
|---|---|---|
| 저널 원고 A | 용어 일괄 치환, 정의부 재작성 | 큼 |
| 저널 원고 B | 용어 치환 | 중간 |
| 학위논문 | 용어 치환, 용어표 등재 | 큼 |
| 다른 분야 원고 | 적용 없음(층위가 다름) | 없음 |

Why: 확정 후 내용을 바꾸지 않고 이름만 바꾸면 기존 수치와 논증을 살릴 수 있다. 교수님도 "나중에 용어만 바꾸면 된다"고 하셨다.

## 10. 소스 표기와 표시 표기의 분리

- 소스(마크다운, 데이터, 코드)에는 안전한 평문 ID를 쓴다. 예: `Lfas`.
- 아래첨자나 이탤릭 같은 수학 표기는 조판이나 렌더링 단계에서만 적용한다. 예: L_fas.
- 수식 기호(|, \mid)는 소스에서 표 셀 안에 리터럴 파이프로 쓰지 않는다. `\mid`로 쓰고, 변환은 렌더 단계에서 한다.
- 이 원칙은 `workflow.md`의 소스 표기 규칙과 같다.
