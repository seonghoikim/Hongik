# 논문 구성 (장절, 서론, 관련연구, 기여, 표 배치)

교수님 연구실 논문의 구성 원리다. 교수님은 구조를 가장 먼저 보신다. 구조가 맞으면 문장은 고칠 수 있지만, 구조가 틀리면 전부 다시 써야 한다.

## 1. 박사논문 6단계 논리 순서

김영철 교수님 박사논문(IIT, 2000)의 방법론 장은 "무엇을 테스트 단위로 볼까 → 어떻게 배치할까 → 어떻게 자동 추출할까 → 실제 사례에 적용 → 무엇을 먼저 할까 → 무엇이 재사용되나" 순서로 전개된다. 새 논문의 방법론 장도 이 순서를 따르고, 도메인 용어만 바꾼다.

| 단계 | 질문 | 전형적 산출물 | 원본 위치(박사논문) |
|---|---|---|---|
| 1. 기본 단위 정의 | 테스트의 기본 단위는 무엇인가 | 단위 유형별 정의와 예시 그림, 유형 열거표 | 4.1 |
| 2. 배치 매트릭스 | 단위를 시나리오별로 어떻게 배치하는가 | 시나리오 × 단위 매트릭스, 상태 경계 | 4.2 |
| 3. 변환 알고리즘 | 설계 다이어그램에서 단위와 매트릭스를 어떻게 추출하는가 | 알고리즘 모듈 구조도 | 4.3 |
| 4. 사례 적용 | 실제 예제에 적용하면 어떻게 되는가 | 유스케이스 → 상호작용 다이어그램 → 단위 → 요약표 | 4.4 |
| 5. 메트릭과 우선순위 | 무엇을 먼저 테스트하는가 | 메트릭 정의표, 확률 계산 그림, 정렬된 시나리오 목록 | 5.1~5.2 |
| 6. 재사용성 | 무엇이 여러 번 쓰이는가 | 재사용 가중치 그림, 공유 부분경로 그림, 종합 표 | 5.3~5.5 |

보조 장: 문제 정의(gap, 3장), 관련연구(2장), 서론(1장), 결론(7장). 단계 2~6은 방법이 바뀌어도 그대로 두는 것이 좋다.

예시(SBIT-VE): 3장 방법론을 1~6단계에 대응시키고, 4장을 사례 적용, 5장을 메트릭과 우선순위, 6장을 재사용성 분석으로 두었다.

Why: 심사자는 새 기법을 기존 틀에 대응시켜 읽는다. 순서가 낯설면 기여가 보이지 않는다.
How: 목차를 먼저 쓰고 위 표의 질문과 한 줄씩 대조한다. 대응이 안 되는 장이 있으면 그 장의 존재 이유를 한 문장으로 쓸 수 있는지 본다.

## 2. 장 구성 표준

### 학위논문 (교수님 박사논문 골격)
- I 서론: 배경, 목적, 개요
- II 관련연구: 테스팅 접근법, 기존 방법론
- III 문제 정의: 무엇이 빠져 있는가 (gap)
- IV 핵심 방법론: 정의 → 매트릭스 → 알고리즘 → 사례 (1절의 6단계 중 1~4)
- V 메트릭: 확률 → 우선순위 → 재사용성 (단계 5~6)
- VI 통합 또는 확장 (교수님 박사논문에서는 성숙도 모델과의 통합)
- VII 결론: 기여와 향후 연구

### 저널 논문 (영문, 짧은 분량)
서론 → 관련연구 → 제안 방법(정의와 알고리즘) → 사례 → 평가 → 논의(위협 요인 포함) → 결론
(권장 골격이다. 원천에 정해진 순서는 없다. 서론·관련연구·결론의 문장 패턴은 이 문서 §3·§4와 `abstract-and-conclusion.md`를 따르고, 가운데 순서는 저자가 정한다.)

서론 끝에는 반드시 "The remainder of this paper is organized as follows..."를 쓴다. 장 시작에는 "In this section, we present..."로 개요를 쓴다. 개요 문단에서는 "First, ... Second, ... Third, ..."로 단계를 신호한다.

## 3. 서론 구성

1. 넓은 맥락(산업, 분야 개요)
2. 좁힌 접근(특정 방법론)
3. 계보 체인: 선행 기여가 점점 확장되는 흐름
4. gap: "However, ... fails to ..." 또는 "... neglects ..."
5. 기여 진술
6. 논문 구성 안내

Kim 방식의 설득 단서: "테스트는 일찍 할수록 좋다(Earlier is better)" 같은 원칙을 서론 첫 단락에 둔다. 비용과 시간을 줄이는 방향으로 논거를 잡는다.

우선순위의 필요성은 문장과 표에 명시한다. 경로 조합이 많아 전부 테스트할 수 없다는 논지를 gap 뒤 문단에 쓰고, 그래서 우선순위가 필요하다고 잇는다. 교수님은 이 논지를 문장과 표에 어떻게 넣을지 물으셨다(2026-08-09).

## 4. 관련연구

- 시작은 범주 제시로 한다. 예: "Three areas of research are relevant..."
- 각 소절은 (a) 선행 기법을 기술하고 (b) 단계를 열거하고 (c) 한계를 지적한 뒤 (d) 본 연구와의 관계를 한 문장으로 쓰고 (e) 다음 소절로 넘어간다.
- 요약만 하지 않는다. 교수님은 "요약하는 것보다 내 접근과 연관해서 요약해야 한다"고 지적하셨다. 각 소절 끝에 "본 연구와의 관계" 문장을 붙인다.
- 관련연구는 비교 분석으로 끝낸다. 비교 축을 열로 둔 표를 쓰면 gap이 한눈에 보인다. 예: 규칙 기반, 모델 기반, AI 에이전트 기반을 열로 두고 "자동 실행", "가상환경 지원", "요구사항 추적" 같은 행을 채운다.
- 인접 분야 문헌(예: 웹 UI 자동화 도구)을 넣을 때는 세 단계로 쓴다. 인정 → 환경 차이(웹 DOM 중심 vs 3D 가상환경) → gap. 교수님은 웹과 가상환경의 차이를 직접 짚으셨다.
- 소절 제목에 '소결'을 쓰지 않는다. 소절 맺음은 본문 단락으로 쓴다.
- 선행 기법은 경쟁 대상이 아니라 보완 관계로 쓴다. 선행 기법은 다른 목표에 맞고, 본 연구는 그 목표가 채우지 못한 부분을 맡는다고 쓴다(예: 최단 경로 탐색은 한 경로를 고르는 데 맞고, 본 연구는 모든 경로 보존을 목표로 한다).

## 5. 기여(C1~C5) 서술

- 기여는 항목마다 "무엇을 새로 했는가"와 "어디서 보였는가(절 번호)"를 함께 쓴다.
- 기여의 순서는 중요도 순이다. 새로 제안한 기법을 첫 항목에 둔다.
- 예시 구성(SBIT-VE): C1 이론적 확장(단위의 4-tuple 정의), C2 교차 도메인 재사용 지표, C3 실험 검증, C4 실행 메커니즘, C5 실무 지침.
- '수단'과 '기법'을 구분한다. 기여 목록에서 '기법'으로 세운 것은 초록과 서론에도 같은 말로 나와야 한다.

Why: 교수님은 기여 목록에 있는 가장 큰 기여가 서사의 중심에 없으면 "잘 안 읽힌다"고 보신다.

## 6. 절 순서 (데이터 흐름)

방법론 장의 절은 데이터가 흐르는 순서로 배치한다. 예: 행위 매트릭스 → 전이 확률 → 우선순위 경로 → 그래프를 트리로 바꾸는 변환.
각 절의 첫 문장은 앞 절의 산출물을 받아 쓴다. 절 순서를 바꾸기 전에 "이 절이 어떤 입력을 받는가"를 확인한다.

## 7. 추적성 매트릭스

요구사항 → 유스케이스 → 시나리오 → 단위 → 검증 ID 순서의 표를 3장이나 부록에 둔다.
Why: 교수님은 요구사항에서 객체와 메소드까지 이어지는 흐름을 보고 싶어 하셨다.
How: 각 행에 ID를 붙이고, 같은 ID를 본문과 결과 표에서 그대로 쓴다.

## 8. 표 설계 규칙

- 행과 열의 순서는 실행 순서(그래프 위상 순서)로 한다. 알파벳 순서는 쓰지 않는다.
- 공통 요소는 블록으로 따로 모으지 말고, 실행 순서대로 두고 색이나 표식으로 구분한다.
- 시나리오 목록은 우선순위 번호(1~N)로 나열한다.
- 도메인별 묶음이 있으면 도메인 열을 병합(rowspan)해서 표시한다.
- 단위 정의 표는 단위 번호 축(U1, U2, …, Un)으로 쓰면 매트릭스형 표와 대응이 쉽다.
- 여러 블록을 합친 통합 그림에서 공통 노드가 여러 자리에 나뉘어 있으면 하나로 병합해 공통 구간이 보이게 한다.

## 9. 제목과 소절 이름

- 금지: '소결', '본 연구의 위치'(대체: '연구 격차와 제안 접근', '기존 연구와의 격차 분석').
- 기법 이름에 구현 방식을 드러내는 단어를 넣을 수 있다(예: '메커니즘', '기법'). 후속 연구의 확장 방향을 제목에 미리 넣지 않는다.
- 재제출 시 제목은 원 제출 제목을 유지하는 것이 기본이다. 바꿀 이유가 분명할 때만 바꾸고, 바꾼 이유를 설명할 수 있어야 한다.

## 10. 약어와 풀네임

- 첫 등장은 풀네임 + 약어 괄호: "Scenario-Based Integration Testing (SBIT)".
- 이후에는 약어를 일관되게 쓴다.
- 교수님은 본문에서 약자 대신 풀네임을 쓰라고 지시하셨다(예: TSP → Traveling Salesman Problem). 본문에 약자가 많으면 풀네임 여부를 다시 본다.

## 11. 그림과 구조

- 글 위주의 논문보다 도식으로 구조를 보이는 논문이 교수님 기준에 맞다. 방법론 설명은 도식으로 먼저 보이고 본문은 그 도식을 풀어 쓴다.
- 새 그림 문법을 만들지 않는다. 교수님의 박사논문 그림 형식을 용어만 바꿔 쓰거나 추상화해서 쓴다.
- 프레임워크 전체를 한 장으로 보여주는 그림(입력 → 단계 → 계층 → 편익)을 반드시 둔다. 부품별 그림만 있으면 탈락 사유가 된다.
- 그림 제작 세부 규칙은 그림 영역의 스킬을 따른다.

## 12. 재현성 서술

- 방법을 단계별로 쓴다. 다른 연구자가 같은 순서로 구현할 수 있어야 한다.
- 블랙박스로 쓰지 않는다. 자동화 도구를 썼다면 이름과 버전을 명시한다. 부록에 재현성 체크리스트를 둔다.
