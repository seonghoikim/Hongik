# 초록(영문·국문), 결론, 제목

## 1. 왜 초록이 가장 중요한가

교수님은 독자가 초록만 읽고 결론의 향후 연구만 읽는다고 지적하셨다. 초록 구조가 맞지 않으면 본문을 아무리 잘 써도 뒤가 읽히지 않는다. 그래서 초록은 본문을 다 쓴 뒤 마지막에 쓴다.

교수님은 학생의 초록 문장을 그대로 고치기보다, 같은 구조로 처음부터 다시 쓰신다. 구조가 맞으면 문장을 살리고, 틀리면 전부 갈아엎는다. 그러므로 먼저 구조를 맞춘다.

## 2. 초록 7단계

| 단계 | 내용 | 일반형 문장(설명용) |
|---|---|---|
| 1. 문제 | 지금 무엇이 문제인가 | "○○ 환경에서 ○○ 테스트는 많은 시간과 비용이 든다." |
| 2. 지금까지의 방식과 주체 | 어떻게 해 왔고 누가 해결하고 있는가 | "지금까지 ○○는 사람이 체크리스트로 수행하거나 규칙 기반 도구로 자동화해 왔다." |
| 3. 미비점과 필요 | 해결이 부족하니 무엇이 있으면 좋은가 | "그러나 ○○ 한계 때문에 출시 기한을 맞추기 어렵다. 시간과 비용을 줄이는 자동화가 필요하다." |
| 4. 제안 | 무엇을 제안하는가 | "본 연구는 ○○ 기법을 제안한다." |
| 5. 메커니즘 | 어떻게 구현했는가 | "○○ 단계를 ○○ 방식으로 구현하고, ○○를 기준으로 실행 순서를 정한다." |
| 6. 사례 | 이해를 돕기 위해 무엇을 적용했는가 | "○○ 사례(도메인 ○개, 시나리오 ○개)에 적용했다." |
| 7. 효과 | 무엇을 얻었는가 | "○○ 기준선(○○)과 비교해 ○○을 얻었다. 수치는 기준선과 함께 쓴다." |

작성 원칙:
- 각 단계를 한 문장 이상으로 채운다. 빈 단계가 있으면 초록이 불완전하다.
- 2단계에 '누가 해결하고 있는가'를 넣는다. 교수님은 2단계에서 "누가 이 문제를 해결하고 있는가"를 물으셨다.
- 3단계에 시대 흐름을 넣는다. 규칙 기반 자동화에서 AI 기반 자동화로 이어지는 흐름을 배경으로 쓴다.
- 5단계에서 메커니즘이 드러나야 한다. "효율적인 방법을 제안한다"처럼 추상적으로 끝내지 않는다.
- 7단계에 편익을 쓴다. 예: 시간 절감, 비용 절감, 결함 위치 특정, 무수정 적용. 교수님은 수치 우수성보다 편익을 보신다.

AI 과장 금지: 제안 방법이 기계 학습이나 LLM 기반이 아니면 "AI 기반 방법"이라고 쓰지 않는다. 'AI 자동화'는 기존 흐름을 설명하는 배경 문장으로만 쓴다. 예: 본 방법은 학습 모델이 아니라 이벤트 매핑으로 동작한다.

길이: 초록은 학회가 정한 분량 안에서 7단계를 모두 담는다. 분량이 빠듯해도 단계를 빼지 않고 문장을 줄인다. 어느 단계를 더 줄일지는 저자가 정한다.

## 3. 영문 초록

- 국문 초록과 같은 7단계, 같은 순서로 쓴다.
- 문장은 `references/english-style.md`의 문형 틀에서 고른다. 창작하지 않는다.
- 첫 문장은 "This paper describes a part of ... for ..."처럼 논문 범위를 한 문장으로 밝히는 틀을 쓸 수 있다.
- 수치 문장은 "A = ○, outperforming B (○)" 형식으로 쓴다(numbers-and-citations.md 참조).
- 영문 초록은 국문 초록을 번역하지 않는다. 같은 구조에서 영문 문형으로 다시 쓴다. 번역체가 생기는 것을 막기 위해서다.

## 4. 결론

결론은 세 부분으로 쓴다.

1. 무엇을 했는가: "This paper presented ..." 또는 "본 논문은 ○○을 제시하였다."
2. 핵심 결과: 번호 목록 (1), (2), (3)으로 짧게. 각 항목은 기준선 비교 수치나 확인된 사실 하나.
3. 향후 연구: 번호 목록으로 쓴다. 각 항목은 짧은 설명과 함께 현재 한계에서 도출한다.

향후 연구 항목의 출처: 한계 절(위협 요인)에서 바로 이어지는 항목을 고른다. 예: 수동으로 만든 시나리오 → 자동 생성, 한 도메인 → 다른 도메인 적용, 가정한 확률 → 실데이터로 보정.

Why: 교수님은 결론에서 향후 연구를 읽는다고 하셨다. 향후 연구가 없는 결론은 연구가 끝난 것처럼 보이지 않고 미완성으로 보인다.
How: 결론을 쓴 뒤 향후 연구 항목이 있는지 확인한다. 없으면 한계 절을 다시 읽고 채운다. 원천은 향후 연구를 "반드시" 쓰라고만 정했고 개수는 정하지 않았다. 항목 수는 한계 절에서 도출되는 만큼 쓴다.

## 5. 핵심 문제 문장의 일관성

- 교수님이 강조하신 핵심 메시지 한 문장("최소의 테스트 케이스로 최대의 커버리지", 같은 종류의 목표 문장)을 초록, 서론, 결론에 같은 말로 둔다.
- 이 문장을 본문에서 처음 쓸 때 '핵심 문제'로 명시하면 심사자가 찾기 쉽다.
- (권장 방법) 서론 마지막 문단에서 핵심 문제 문장을 쓰고, 결론에서 "본 논문은 핵심 문제인 ○○를 ○○로 해결하였다"로 되돌린다.

## 6. 제목

- 재제출(revision)에서는 원 제출 제목을 유지하는 것이 기본이다. 제목이 달라지면 같은 논문인지 심사자가 헷갈릴 수 있다.
- 제목 어순은 자유롭지만, 핵심 키워드(방법, 대상, 목적)는 빠지지 않게 한다.
- 교수님 승인을 받은 제목 형식은 그대로 쓴다. 영문 제목 패턴은 `references/english-style.md`의 제목 틀을 참조한다.
- 발표 제목과 논문 제목은 같은 키워드를 쓴다. 후속 연구의 방향(예: 자동화)은 제목이 아니라 결론의 향후 연구에 쓴다.

## 7. 체크리스트

- [ ] 초록에 7단계가 모두 있는가
- [ ] 2단계에 기존 방식의 주체가 있는가
- [ ] 5단계에 메커니즘이 드러나는가
- [ ] 7단계 효과가 기준선과 함께 있는가
- [ ] 제안 기법이 학습 기반이 아닌데 'AI 기반'이라고 쓰지 않았는가
- [ ] 영문 초록이 국문 초록의 번역이 아니라 같은 구조의 영문 문형인가
- [ ] 결론에 향후 연구 항목이 있는가
- [ ] 핵심 문제 문장이 초록, 서론, 결론에 같은 말로 있는가
- [ ] 재제출이면 제목이 원 제출과 같은가
