# 김영철 교수님 기준 논문 작성

방법론 중심 공학 논문을 교수님 연구실 방식으로 쓰고 검수하는 절차와 규칙이다. 각 규칙에는 Why(왜)와 How(어떻게)를 함께 적었다. 예시로 든 SBIT-VE(가상환경 시나리오 기반 통합 테스트)는 설명용이다. 다른 주제에 적용할 때는 도메인 용어만 바꾼다. 세부 근거와 문형은 `references/`를 읽는다.

## 0. 범위와 필요 조건

- 범위: 텍스트(마크다운 등)로 관리하는 원고의 구성, 문장, 용어, 수치, 인용, 발표 구성.
- 범위 밖: 그림 제작, DOCX·PPT 조판 자동화, 학회 투고 시스템. 별도 스킬 영역이다.
- 필요 조건: 원고 파일을 읽고 쓸 수 있어야 한다. 수치를 검증하려면 수치의 원천(계산 스크립트, 결과 파일)이 있어야 한다. 새 참고문헌의 DOI 확인에는 `scripts/academic_search.py verify <DOI>`를 쓰며 인터넷 연결이 필요하다.
- 용어: 'Kim'은 김영철 교수님이다. 교수님 박사논문(IIT, 2000)이 방법론 구조의 원본이다.
- 시작 전 확인: 정본 파일, 버전 이력 문서, 최근 교수님 피드백 체크리스트, '판단 필요' 미결 항목.

## 1. 작업 절차

1. 현황 파악: 피드백 체크리스트와 미결 항목부터 읽는다. → `references/feedback-history.md`, `references/workflow.md`
2. 구조 점검: 장절 순서를 박사논문 6단계 순서와 대조한다. → `references/structure.md`
3. 절 작성: 개념은 정의 4단으로, 선행연구는 인정 → However → Thus로, 수치는 기준선과 함께 쓴다. → `references/definitions-and-gap.md`, `references/numbers-and-citations.md`
4. 문장 작성: 영문은 문형을 재사용하고, 국문은 번역체를 없앤다. → `references/english-style.md`, `references/korean-style.md`
5. 용어 점검: 새 용어는 확정 절차를 거친다. → `references/terminology.md`
6. 초록과 결론: 마지막에 쓴다. 초록은 전체 구조의 요약이다. → `references/abstract-and-conclusion.md`
7. 검수: stylechk(연구실 7항목 검수, review-criteria §9)와 린트 스크립트를 돌린다. → `references/review-criteria.md`. 린트는 키트 루트에서 `python scripts/style_lint.py <원고.md> [--ban 금칙어1,금칙어2] [--json]`로 실행한다. error는 반드시 고치고, warn은 문맥을 보고 판단한다.
8. 저장과 보고: 새 버전 파일로 저장하고 변경 체크리스트로 보고한다. → `references/workflow.md`

발표 자료나 심사 답변을 만들 때는 `references/presentation.md`와 `references/review-criteria.md`를 함께 읽는다.

## 2. 핵심 규칙

**R1. 구조가 먼저다.** 교수님 피드백의 우선순위는 구조, 사례 다양성, 확률 근거, 그림, 문체 순이다. 구조가 맞으면 기존 문장을 살려 고치고, 틀리면 전면 재작성해야 해서 검토 자체가 미뤄진다.
- How: 장 제목 목록을 먼저 만들고 박사논문 6단계와 한 줄씩 대조한다.

**R2. 초록은 7단계로, 결론에는 향후 연구를 반드시 쓴다.** 독자는 초록과 결론의 향후 연구만 읽는다.
- How: 문제 → 기존 방식과 주체 → 미비점 → 제안 → 메커니즘 → 사례 → 효과 순으로 채운다. 빈 단계가 있으면 초록을 다시 쓴다.

**R3. 정의는 '정의 → 예시 → 논의 → 적용' 4단으로 쓴다.** 소절 제목 아래 항목 네 개를 둔다. 영문은 `1) Definition: 2) Example: 3) Discussion: 4) Application:`, 국문은 `1) 정의: 2) 예시: 3) 논의: 4) 적용:`. `Definition 1 (…)` 같은 번호 체계와 `Algorithm 1.` 번호는 쓰지 않는다.

**R4. 단위 입도(granularity)를 정의 본문에 명시한다.** 무엇을 한 단위로 자르는지, 판정 기준(관찰 가능성, 검증 가능성, 원자성)이 무엇인지 쓴다. 단위가 아닌 예와 단위인 예를 나란히 보인다.
- Why: 심사자는 "클릭 한 번인가, 구매 한 번인가"를 묻는다.

**R5. 단위 계층을 3층으로 보인다.** 원자 단위 → 중간 덩어리 → 시나리오. 시나리오가 너무 크면 설명과 재사용의 단위가 맞지 않는다.

**R6. 선행연구는 인정 → However → Thus로 쓴다.** 선행 기여를 먼저 인정하고, 구체적 빈 곳(gap)을 지적한 뒤, 본 연구가 그 빈 곳을 채운다고 쓴다. 인접 분야 문헌은 '환경의 차이'를 한 문장 더 넣는다.

**R7. 새로 제안한 기법을 기여의 첫머리에 둔다.** 수단처럼 한두 번 언급하고 넘어가면 가장 큰 기여가 묻힌다.

**R8. 최적화와 비최적화를 구분하고, 용어를 정확히 쓴다.** 하나의 최적해를 찾는 방법과 모든 경로를 보존하는 방법을 섞지 않는다. maximal(더 가지를 칠 수 없는)과 maximum(가중치 합이 최대인)은 뜻이 다르다.

**R9. 수치는 기준선과 함께 쓰고, 한 원천에서 나오게 한다.** 예: "A = 0.772, 무작위 0.500". 산출 근거(스크립트, 데이터 파일)가 없는 수치는 본문에 두지 않는다.

**R10. 열거가 가능하면 몬테카를로를 쓰지 않는다.** "정확(exact)"과 "샘플링"을 같은 문장에서 쓰지 않는다.

**R11. 확률과 가중치의 근거는 세 겹으로 댄다.** 전문가 판단, 체계적 도구(예: AHP, 일관성비율 CR ≤ 0.10), 실데이터. 실데이터가 없으면 '향후 보정'으로 분리하고 실험 근거로 쓰지 않는다.

**R12. 영문은 창작하지 않는다.** 교수님이나 저자 자신의 기존 문장 구조(문형)를 고르고 내용만 넣는다. 은유, 의인화, 질문-답 수사, 강조 부사는 걷어낸다.

**R13. 국문에서 번역체 동사를 쓰지 않는다.** '덮다, 몫이다, 낳다, 세우다, 메우다, 갭' 류는 학술 한국어로 바꾼다. 용어는 영어 그대로 두고 첫 등장에 병기한다.

**R14. 용어는 확정 절차를 거친다.** 한국어와 영어 사전을 모두 대조하고, 의미 층위를 나누고, 교수님 확정 후 전역 치환한다. 영어 사전 한쪽만 보고 정하면 나중에 뒤집힌다.

**R15. 인용은 계보가 보이도록 쓴다.** 방법론 접점마다 자기 계보를 인용하고(예: Kim [1][2]), 연속 대괄호 `[1][2]`를 쓰며, 쉼표 `[1,2]`는 쓰지 않는다(단, 저널 규정이 쉼표형이면 저널을 따른다 — 예: 정보처리학회 논문지는 `[1, 2]`, `[1-3]`). 번호를 주어로 쓰지 않는다(`[23]은` 금지, `Qi 등[23]은`). 새 문헌은 DOI를 확인한 뒤 추가한다.

**R16. 모호한 말과 금칙 제목을 쓰지 않는다.** "공통 흐름"처럼 무엇이 공통인지 불분명한 말 대신 "포함", "공유 구간"처럼 관계를 쓴다. 절 제목 '소결', '본 연구의 위치'는 쓰지 않는다. 절 맺음은 본문 단락으로 한다.

**R17. 표는 실행 순서로 쓴다.** 행과 열은 그래프상 실행 순서로 나열한다. 공통 요소는 색이나 표식으로 표시하고, 공통과 특화를 블록으로 나누지 않는다.

**R18. 핵심 메시지 한 문장을 일관되게 둔다.** 초록, 서론, 결론에 같은 문제 문장을 쓴다.

**R19. '왜 이 선택인가'를 쓴다.** 대안의 장점을 인정하고, 목표가 다르다는 점을 밝히고, 선택 이유를 쓴다.

**R20. 교수님이 직접 고친 문장은 건드리지 않는다.** 교정본과 직전본을 비교해 교정 패턴만 뽑아 새 원고에 적용한다.

**R21. 저자가 책임질 수 있는 문장만 남긴다.** AI가 만든 초안은 저자가 직접 읽고 고친다. 학습 기반이 아닌 방법을 'AI 기반'이라고 과장하지 않는다.

## 4. 금지 목록 (요약)

- 절 제목 '소결', '본 연구의 위치', 정리식 번호 `Definition 1 (…)`, `Algorithm 1.`
- 번역체: 덮다, 몫이다, 낳다, 세우다, 메우다, 갭, 동반 연구, 짚어 낸다, 책임을 묻는다
- 본문 질문형 문장, 은유, 의인화, 구어체(~거든요)
- 영문 1인칭 I (we 사용), 수동 'was proposed by', 강조 부사(actually, at all)
- 쉼표 인용 `[1,2]`, 번호 주어 `[23]은`
- 산출 근거 없는 수치, 기준선 없는 수치 나열, '정확'과 '샘플링'의 동시 사용
- 열거가 가능한데 몬테카를로로 근사하는 것
- 공통과 특화의 블록 분리, 알파벳 순서로 된 표(실행 순서가 아닌 경우)
- 재제출에서 근거 없이 제목 바꾸기
- 확정된 용어를 되돌리기, 한쪽 사전만 보고 용어 정하기

```
## 변경 사항

## 파일
- 새 버전: <파일명>_v{번호}.md (기존 파일은 그대로 둔다)
```

## 6. 예시와 일반 규칙의 구분

- SBIT-VE, 가상 쇼핑몰, 특정 수치와 같은 내용은 설명용 예시다. 다른 원고에 옮길 때는 규칙만 가져간다. 예시의 수치와 용어는 시점마다 바뀌었으므로, 실제 원고에 쓰기 전에 저자가 원천에서 다시 확인한다.
- 예시에 나오는 약어 풀이: BU(행위 단위, 초기 명칭 behavior unit), TAAU(테스트 에이전트 행위 단위, test agent's action unit), DU(다이얼로그 단위, 액터 입력에서 출력까지 왕복하는 부분 다이어그램), MLU(최대 직선 구간), R_path(부분경로 재사용성), P_occ(경로 발생 확률), CDR(교차 도메인 재사용 지표), APFD(우선순위 순서의 평균 결함 검출 백분율, 0~1, 클수록 결함을 일찍 찾음), SISO(단일 입력 단일 출력 병합), AHP(계층분석법), CR(쌍대비교의 일관성비율).
- 교수님 피드백에서 나온 교훈은 날짜와 함께 `references/feedback-history.md`에 있다. 같은 지적이 다시 나오면 그 항목을 먼저 확인한다.
- 충돌하면 가장 최근의 교수님 확정 판단을 따른다. 낡은 가이드(예: 정리식 정의 번호)보다 최신 원문 확인이 우선이다.
