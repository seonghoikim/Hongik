# 원서 그림 대응 방법 — 지도교수 학위논문 문법 따르기

지도교수 컨펌의 핵심 요구는 방법론 그림을 **원서(지도교수의 박사 학위논문) 그림 문법**에 맞추는 것이다. 이 문서는 원서의 그림을 우리 논문의 그림과 짝지어, 빠진 그림과 형식이 다른 그림을 찾는 방법을 정리한다. 프로젝트의 원서는 2000년 IIT 박사 학위논문이다. 다른 연구자는 자기 지도교수의 원서나 기준 논문으로 바꿔 쓴다.

## 1. 목적

- 원서 그림의 **역할**을 우리 논문에서 빠짐없이 맞춘다.
- 역할은 같아도 **문법**이 다르면 원서 문법으로 다시 그린다.
- 우리 논문에만 있는 그림은 **고유 기여**로 설명하고 삭제하지 않는다.
- **Why:** 지도교수는 그림이 원서 수준으로 갖춰졌는지 본다. 같은 연구실의 선행 학위논문은 그림을 20~30개 수준으로 두었고, 프로젝트 논문은 그보다 적어 보완 지시를 받았다. 대응표가 없으면 무엇이 빠졌는지 근거를 대기 어렵다.

## 2. 절차

1. **원서 그림 페이지를 확보한다.** 텍스트 층이 있으면 `extract_pdf_figures.py --render-pages`로 페이지를 PNG로 뽑는다. 스캔본이면 같은 방법이 필수다.
2. **원서 그림을 직접 본다.** 본문 설명만 읽고 대응을 판단하지 않는다. 보고된 판독이 실제 그림과 달랐던 사례가 있다 (`pitfalls.md` §5).
3. **역할로 짝을 짓는다.** 입력, 출력, 경계, 단위의 입도가 같은지 보고 짝을 정한다 (§3).
4. **상태를 판정한다.** 판정 4분류 (§3.2).
5. **대응표를 쓴다.** 양식은 §5.
6. **우선순위와 제작 순서를 정한다** (§6).

## 3. 대응 판정 기준

### 3.1 이름이 아니라 정의로 판정한다

이름이 같다고 같은 그림이 아니다. 아래 네 가지를 비교한다.

- **입력과 출력:** 무엇을 받아 무엇을 내는가.
- **경계:** 어디서 끊어 한 덩어리로 보는가 (상태 경계, 왕복 경계).
- **입도:** 한 덩어리가 메시지 하나인가, 메시지 여러 개의 묶음인가, 왕복 구간인가.
- **재사용 단위:** 여러 시나리오에서 같은 덩어리가 반복되는가.

### 3.2 판정 4분류 (+ 재분류)

| 상태 | 뜻 | 조치 |
|------|-----|------|
| **matched** | 역할과 문법이 같다 | 기존 그림 유지, 설명만 연결 |
| **재작 (양식 불일치)** | 역할은 같고 문법이 다르다 | 원서 문법으로 다시 그린다 |
| **partial** | 역할의 일부만 같다 | 빠진 요소를 추가해 구조를 개선한다 |
| **missing** | 대응이 없다 | 새로 만든다 |
| **extra** | 원서에 없는 우리 고유 그림 | 기여로 설명한다. 삭제하지 않는다 |

**재분류:** 짝을 잘못 지었다고 판명되면 올바른 대응을 다시 찾는다. 프로젝트 사례 두 가지:

- **입도가 다른 경우:** 원서의 "왕복 단위"(입력에서 출력까지 전체를 음영으로 묶는 단위)를 우리 쪽의 "한 메시지 단위"에 짝지었다가, 왕복 구간이 여러 단위의 합성이라는 것을 알게 됐다. 짝을 구간에 맞추고, 그림도 왕복 폐곡선 문법으로 다시 그렸다.
- **내용은 맞고 형식이 다른 경우:** 원서에서는 표-그림 형식인데 우리 쪽은 산점도였다. 내용 대응은 유지하고, 형식만 원서 형식으로 바꿨다.

## 4. 원서 문법 레퍼런스 (재작 규격)

프로젝트에서 원서 그림을 본 뒤 정리한 요소별 문법이다. 원서마다 다를 수 있으므로 자기 원서를 직접 보고 같은 표를 만든다.

| 요소 | 원서 문법 (프로젝트 기록) | 재작 규칙 |
|------|-------------------------|-----------|
| 상호작용 다이어그램 | 액터는 검은 타원, 객체는 사각 (제어 객체는 상단 표시), 수직 생명선, 수평 메시지 화살표 | 같은 배치를 유지하고 용어만 바꾼다 |
| 단위 표시 | 메시지 묶음을 둥근 상자나 음영 폐곡선으로 감싸고 굵은 라벨을 단다. 오른쪽에 `a = m1 + m2` 같은 텍스트 범례 | 묶음을 같은 방식으로 감싼다 |
| 상태 | 생명선 위의 원 안에 상태 `s0`, `s1` … 상태 사이 구간은 점선 상자 | 상태 원과 점선 구간을 쓴다 |
| 다이얼로그 맵 | 원 노드(단위 ID), ● 시작, ◉ 끝, 간선 확률은 이탤릭, 설명 라벨은 이탤릭, 경로 강조는 굵은 선 | 같은 기호로 그린다 |
| 매트릭스 | 행 = 시나리오, 열 = 단위, 셀 = 실행 순서 정수. 도형 오버레이로 공유도 표시 (타원 = 3경로, 둥근 사각 = 2, 삼각 = 1). 묶음은 굵은 테두리 | 공유도를 도형 개수로 표시한다 |
| 알고리즘 | Nassi–Shneiderman 구조 차트(순서도 대신 중첩 상자로 제어 흐름을 그리는 문법): 중첩 상자, 대각선 yes/no 분기 헤더, Do-While은 ㄴ자 띠 | 순서도 대신 구조 차트를 쓴다 |
| 다이어그램 → 매트릭스 | 큰 속 빈 화살표 ⇨ | 같은 화살표로 연결한다 |

- **Why:** 교수님은 새 그림 문법을 발명하지 말고 원서의 그림 포맷을 쓰라고 했다. 독자가 원서를 본 적이 있다면 그림만 보고 구조를 알아본다.

## 5. 대응표 양식

양식 예시 (ID는 가상의 예):

| 원서 ID | 원서 제목 | 우리 ID | 우리 제목 | 상태 | 격차 | 조치 | 우선순위 |
|---------|-----------|---------|-----------|------|------|------|----------|
| Fig 4.15 | (원서 그림 제목) | 그림 13 | (우리 그림 제목) | partial | 매트릭스 표 없음 | 행 × 열 매트릭스 표 추가 | high |

- 표 아래에 집계 한 줄을 쓴다: matched N, 재작 N, partial N, missing N, extra N.
- **판정 근거를 칸으로 남긴다:** 원서 페이지 번호, 원서 그림 ID, 우리 그림 파일명. 심사 질문에 바로 답하려면 이 근거가 필요하다.
- **나란히 대조한다:** 원서 그림 페이지 PNG와 우리 그림 PNG를 좌우로 놓은 HTML 한 장을 만들어 검토한다 (프로젝트 기록: 나란히 대조 페이지). 문법 요소(생명선, 음영 묶음, 도형 오버레이)가 빠졌는지 한눈에 본다.
- 표 자체도 그림 문법과 같은 기준으로 쓴다 (`figure-style.md`).

## 6. 우선순위와 제작 순서

- **high:** 방법론의 핵심 흐름(알고리즘, 확률, 단위 정의)에 해당하는 그림. 먼저 만든다.
- **medium:** 논리 완결을 위해 필요한 그림. 패턴 분류, 상태 예시, 공통성 분석.
- **low:** 필수는 아니지만 원서에 있는 그림. 시간이 남으면 만든다.
- 작업량은 그림마다 추정치를 쓰고, 추정이 틀리면 갱신한다. 전체 로드맵은 체크리스트로 관리한다.

**승인 게이트 (프로젝트 절차).** 판정표를 먼저 쓰고, 저자가 승인한 뒤에 재작한다. 프로젝트에서는 아홉 쌍의 대응 타당성을 판정표로 정리해 승인을 받았다. 타당한 쌍은 원서 문법으로 재작하고, 애매한 쌍은 재분류했다. 승인 전에 기존 그림을 바꾸지 않는다.

## 7. 주의

- **원서 그림을 본문에 그대로 싣지 않는다.** 문법만 가져오고, 그림은 우리 자료로 새로 그린다. 원서 그림을 복제하면 저작권 문제가 생긴다.
- 원서의 한 그림을 우리 논문의 여러 그림에 나눠 짝지을 수 있다. 짝이 1:1이라고 가정하지 않는다.
- 우리 논문에 있는 그림이 원서에 없다면 `extra`로 두고, 고유 기여로 설명하는 문단을 본문에 둔다.
