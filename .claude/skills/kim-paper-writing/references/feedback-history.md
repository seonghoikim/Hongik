# 교수님 피드백 연대기 (일반화)

회의별 요지를 일반화한 기록이다. 같은 지적이 다시 나오면 먼저 여기서 관련 항목을 찾는다. 특정 연구의 수치와 내부 사정은 뺐고, 교훈만 남겼다.

## 2. 번복된 판단 (되돌리지 않을 것)

| 번복 | 바뀐 내용 | 이유 |
|---|---|---|
| 'maximum' → 'maximal' (2026-09-19) | 트리 이름은 극대(maximal)다 | 가중치 합 최대(maximum)와 뜻이 다르다. 알고리즘은 가지를 치지 않는다. |
| 몬테카를로 → 전수 열거 (2026-07-25) | 열거 가능하면 전수 열거 | 열거 가능한 문제에 근사를 쓰면 '정확'과 모순된다. |
| 'behavior' 권고 → 'action' (2026-08, 권고 철회) | 낱개 단위는 action, 묶음은 behavior | 한국어 뜻풀이 대조 누락. 철회. |
| 'AR' → 'AHP' (2026-07-25) | 이미 구현된 AHP로 확인 | 녹취 해석 오류. 데이터 파일로 확인. |
| 구 게재 수치 폐기 (2026-07-22) | 재계산 값으로 교체 | 산출 근거가 없었다. |
| 정리식 정의 번호 → 소절 + 4항목 (2026-10-02) | 소절과 항목 네 개 | 교수님 박사논문 원문 확인. |

## 3. 피드백 처리에서 반복된 교훈

1. 구조가 승인되면 구조를 바꾸지 않는다. 추가와 정정만 한다.
2. 교수님이 "잘했다"고 한 그림과 문장은 변경 목록에서 제외하고 그대로 둔다.
3. 녹취는 품질이 낮다. 해석은 원음 타임스탬프, 손글씨, 데이터 파일로 확인하고, 불확실한 곳은 표시한다.
4. 저자의 정리본이 녹취 해석을 대체한다. 충돌하면 저자에게 확인한다.
5. 교수님이 직접 고친 문장은 건드리지 않는다.
6. 대외 공개를 제한한 내용은 공개 원고에 넣지 않는다.

## 4. 우선순위 (학생 정리 기준)

구조 > 사례의 다양성 > 확률 근거 > 그림 > 문체. 구조가 틀리면 나머지 피드백이 소용없다. 같은 우선순위로 체크리스트를 정리한다.
