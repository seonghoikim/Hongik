# 교수님 피드백 루프 (kim-feedback-loop)

교수님 피드백을 받아 논문을 고치고, 그 과정을 나중에 추적할 수 있게 남기는 절차와 규율이다.
김영철 교수님 컨펌 기준을 맞추려고 쌓은 규칙을 일반화했다. 특정 논문의 수치와 사례는 예시로만 쓰며, 규칙은 다른 주제에도 그대로 적용한다.

## 0. 필요 조건

- OS: Windows 10/11, Git Bash 또는 PowerShell. 경로는 `C:/...` 또는 `/c/...` 로 쓴다.
- Python 3.10 이상. `pip install faster-whisper requests` (조판 자동화를 쓰면 `pip install pywin32`).
- ffmpeg 실행 파일. PATH에 등록하거나 `--ffmpeg <경로>` 로 지정한다.
- DOCX 편집은 pywin32 Word COM만 쓴다. XML 직접 수정은 금지한다. 한글(HWP) 자동화는 정식 한글 프로그램이 필요하다. 세부 조판 규칙은 조판 전용 스킬을 따른다.
- `${KIT}` 는 이 키트 루트 폴더(`scripts/` 가 있는 곳)다. Git Bash 에서 `export KIT=<키트 절대경로>` 로 지정한 뒤 호출한다. 프로젝트에 복사해 쓴다면 그 프로젝트의 `scripts/` 경로를 넣는다.
- 문서에서 "원천"은 이 규칙을 뽑아낸 원본 연구 프로젝트를 뜻한다. 사례와 수치는 그 프로젝트의 것이며 예시로만 읽는다. 예시에 나오는 약어도 그 연구의 용어다. APFD(결함 검출 순위의 평균 백분율 지표), BU(행동 단위, Behavior Unit), TIIS·IJIBC(저널 이름 예시)는 자기 연구 용어로 바꿔 읽는다.
- 개인 경로, 계정, 이메일, 공저자 실명은 키트 문서에 넣지 않는다. 프로젝트의 `CLAUDE.md` 나 개인 메모에 둔다.

## 1. 불변 규칙 (모든 작업에 적용)

| # | 규칙 | 이유 | 방법 |
|---|---|---|---|
| 1 | 기존 파일을 덮어쓰지 않는다. 산출물은 `_v{N}` 또는 타임스탬프가 붙은 새 파일로 저장한다 | 교수님이 본 판본과 대조할 수 있어야 하고, 덮어쓴 판본은 복구되지 않는다 | 저장 전 존재 여부 확인. 스크립트는 `_v2`, `_v3` 를 자동으로 붙인다 (versioning.md) |
| 2 | 순서를 지킨다: 녹음 → 전사 → 피드백 표 → 체크리스트 → 새 버전 → 자가 검사 → 보고 | 체크리스트 없이 원고를 고치면 교수님 지적을 빠뜨린다 | 각 단계 산출물을 파일로 남긴다 |
| 3 | 프로젝트 `CLAUDE.md` 의 교수님 우선순위를 따른다 | 교수님이 보는 순서와 작업 순서가 같아야 한다 | 기본 예: 논문 구조 > 사례·실험 다양성 > 근거(확률·수치) > 그림 > 문체 |
| 4 | 발언에는 녹취 시각 `[mm:ss]` 를 단다. 불분명한 발언은 `(해석)` 으로 표시한다 | 원 발언을 나중에 확인할 수 있어야 하고, 추측이 사실처럼 쓰이면 안 된다 | voice-feedback.md |
| 5 | 수치는 재현 가능한 산출 근거에서만 가져온다 | 문서에 적힌 숫자가 근거 없이 굳어진 사례가 있었다 | numeric-authority.md |
| 6 | 수작업을 '자동'이라 쓰지 않는다. 못 한 실험은 '미실시'로 쓴다. 유의하지 않은 결과를 유의하다고 쓰지 않는다 | 연구 진실성, 심사에서 가장 먼저 검증되는 부분 | research-integrity.md |
| 7 | 참고문헌은 DOI 검증 후에만 추가한다 | 존재하지 않는 서지가 원고에 들어가는 것을 막는다 | references-verification.md |
| 8 | bash 에서 `>nul` 을 쓰지 않는다 (`>/dev/null` 을 쓴다). 백슬래시가 든 패치는 heredoc 으로 넣지 않고 파일로 작성해 실행한다 | `nul` 파일이 생기면 `git add` 가 죽고 백업 hook 이 조용히 멈춘다. heredoc 은 `\t`, `\f`, `\frac` 를 제어문자로 바꾼다 | versioning.md 3절, 7절 |
| 9 | 완료 보고는 체크리스트로 하고, 생성 파일은 절대경로로 적는다 | 검토자가 바로 열어 볼 수 있어야 한다 | 5절 |

## 2. 작업 절차

### Step 1. 녹음 확보
- 사용자가 경로를 주면 그 파일을 쓴다. 없으면 작업 폴더에서 가장 최근 `.m4a` 를 찾는다 (`ls -t *.m4a | head -1`).
- 보고에 파일명과 길이를 적어, 엉뚱한 녹음을 처리하지 않았는지 확인할 수 있게 한다.

### Step 2. 전사 (`${KIT}/scripts/transcribe_meeting.py`)
```
python "${KIT}/scripts/transcribe_meeting.py" "<녹음.m4a>" --tag <작업명> --out-dir "<작업 폴더>" --terms "<전문 용어, 쉼표 구분>"
```
- 청크 계획만 먼저 보려면 `--plan-only` 를 붙인다. 기본 청크 길이는 8분이라 8분 이하 녹음은 자동으로 한 청크가 된다. 더 긴 녹음을 단일 스트림으로 돌리려면 `--chunks 1` 을 붙인다.
- 중단되면 같은 명령을 다시 실행한다. 저장된 청크는 건너뛴다.
- 결과: `<작업명>_<모델>.txt` (`[mm:ss] 텍스트` 형식) 와 `_segments.json`. 같은 이름이 있으면 `_v2` 를 붙인다.
- 자세한 옵션과 교훈은 voice-feedback.md.

### Step 3. 피드백 정리
- `feedback_YYYYMMDD.md` 를 새로 만든다. 같은 날 파일이 있으면 `_v2` 를 붙인다.
- 구성: 결정 사항 표(시각 인용 포함), 미결 사항, 체크리스트. 원문 전문은 본문에 넣지 않고 전사 파일을 가리킨다.
- 템플릿은 voice-feedback.md 4절.

### Step 4. 체크리스트
- 한 항목은 `무엇을 · 어디서 · 완료 기준 · 근거 시각` 으로 쓴다.
- 예: `- ☐ [P1] 3.2절 BU 정의에 정의-예시-논의-적용 4단계 추가 (완료: 4단계 모두 존재) [03:12]`
- 우선순위 [P1]~[P4] 는 voice-feedback.md 5절.

### Step 5. 새 버전
- 최신 판본 번호를 찾아 다음 번호를 정한다 (`v07` → `v08`). 원본은 건드리지 않고 복사본에 작업한다.
- 수정은 패치 스크립트(파일)로 한다. 직접 편집보다 재현과 롤백이 쉽다 (versioning.md 2~3절).

### Step 6. 자가 검사
- 기계 검사: 제어문자(`[\t\f\v\b]`) 없음, 수치 대조, 인용 번호 대조, 답변서 `@CHANGES` 위치가 실제 원고에 존재하는지.
- 사람 검사 항목: 교수님 결정 반영 여부, 번역체 여부 (4절), 미결 항목 표시.

### Step 7. 보고
- 체크리스트 형식으로 보고한다 (5절). 생성 파일은 절대경로로 적는다.

심사 대응 작업이면 Step 3~6 대신 revision-response.md 절차를 쓴다.

## 4. 문체 (한글 원고·보고)

- 번역체 동사를 쓰지 않는다. 덮다, 몫이다, 낳다, 세우다, 메우다, 갭(gap), 동반 연구 류가 대표적이다. 교수님 검토 문서라 문체가 곧 신뢰도다.
  - 덮다 → 포함하다 · 몫이다 → 사람이 수행한다 · 낳다 → 얻는다 · 세우다 → 정한다 · 메우다 → 해결한다 · 갭 → 문제, 한계 · 동반 연구 → 선행 연구
- 은유, 의인화, 수사 의문문("누가 실행하는가?")을 피한다.
- 프로젝트 약어와 도구 이름(예: Playwright)은 영어 그대로 쓰고, 첫 등장에 풀어 쓴다. 검토자가 풀이 없이 알 수 없는 약어는 본문에 두지 않는다.
- 간결하게 쓴다. 교수님이 "간단히 하자"고 하면 답변과 보고 분량을 줄인다.
- 영문 원고는 프로젝트의 영문 문체 메모를 따른다.

## 5. 작업 완료 체크리스트 (보고 형식)

- ☐ 산출물 목록 (절대경로, 모두 새 이름인지 확인)
- ☐ 교수님 결정 사항 반영 여부 (항목별)
- ☐ 미결 사항 (교수님 판단 필요 항목)
- ☐ 자가 검사 결과 (제어문자, 수치 대조, 참고문헌 verify, 답변서 위치)
- ☐ 중간본 보존 여부 (삭제하지 않았거나, 삭제 대상을 목록으로 제시해 승인을 받았는지)
- ☐ 변경 요약 (절·표·그림 단위)
- ☐ 자동 백업 hook 이 있는 저장소라면 커밋 메시지는 한글 동사형으로 시작한다 (추가:, 수정:, 삭제:, 개선:)
