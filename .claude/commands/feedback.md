지도교수 음성 피드백을 처리한다. 절차와 규칙은 키트 스킬 `kim-feedback-loop` 을 따른다.
먼저 `kim-feedback-loop` 의 SKILL.md 와 `references/voice-feedback.md` 를 읽는다.

## 경로 변수

- `<KIT>`: 키트 루트의 절대경로 (프로젝트 CLAUDE.md 에 적혀 있다)
- `<PROJECT>`: 논문 작업 폴더의 절대경로 (프로젝트 CLAUDE.md 에 적혀 있다)
- 경로는 `C:/...` 형식으로 쓴다. Git Bash 의 `/c/...` 는 Python 안에서 모듈을 찾지 못한다.

## 절차

1. **녹음 확보**
   - 인자 `$ARGUMENTS` 가 있으면 그 파일을 쓴다.
   - 없으면 `<PROJECT>` 에서 가장 최근 `.m4a` 를 찾는다. 파일명과 길이를 보고에 적어 엉뚱한 녹음을 처리하지 않았는지 확인하게 한다.
2. **전사**
   - `python "<KIT>/scripts/transcribe_meeting.py" "<녹음>" --tag <작업명> --out-dir "<PROJECT>/feedback" --terms "<전문 용어, 쉼표 구분>"`
   - 긴 녹음은 청크로 나뉘고 체크포인트가 남는다. 중단되면 같은 명령을 다시 실행한다.
   - 청크 계획만 보려면 `--plan-only` 를 붙인다.
   - 전사 결과는 `[mm:ss] 텍스트` 형식이다. 같은 이름이 있으면 `_v2` 를 붙인다. 기존 파일을 덮어쓰지 않는다.
3. **피드백 문서**
   - `feedback_YYYYMMDD.md` 를 새로 만든다. 같은 날 파일이 있으면 `_v2` 를 붙인다.
   - 구성: 결정 사항 표 (발언 시각 `[mm:ss]` 포함), 미결 사항 (교수님 판단 필요), 체크리스트. 전문은 본문에 넣지 않고 전사 파일을 가리킨다.
   - 불분명한 발언은 원문을 옮기고 `(해석)` 을 붙인다. 추측을 사실처럼 쓰지 않는다.
4. **체크리스트**
   - 한 항목은 `무엇 · 어디서 · 완료 기준 · 근거 시각` 으로 쓴다.
   - 예: `- ☐ [P1] 3장 단위 정의에 정의-예시-논의-적용 4단 추가 (완료: 4단 모두 존재) [03:12]`
   - 우선순위 기본값: 논문 구조 > 사례와 실험 다양성 > 근거 (확률, 수치) > 그림 > 문체.
   - 프로젝트 CLAUDE.md 에 다른 우선순위가 적혀 있으면 그것을 따른다.
   - 교수님이 "잘했다"고 한 항목은 변경 목록에서 빼고 승인 목록에 따로 적는다.
5. **보고**
   - 체크리스트 형식으로 보고한다. 생성 파일은 절대경로로 적는다.
   - 녹음 파일명과 길이, 전사 모델, 청크 수를 함께 적는다.

## 금지

- 기존 파일 덮어쓰기. 산출물은 항상 새 이름 (`_v2`, `_v3` …)으로 만든다.
- 교수님 발언에 없는 결정을 결정 사항에 넣기.

구조 변경이 필요한 피드백이면 체크리스트 작성 후 `/newversion` 으로 새 버전을 만든다.
