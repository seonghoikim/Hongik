# 본 실험 설계 결정 기록 (2026-10-16)

난이도 탐색 NO-GO와 그 뒤의 진단(`docs/probe_diagnosis_20261016.md`, `docs/probe_condition2_20261016.md`,
`docs/oracle_phone_check_20261016.md`, 조건 1·4는 `claude/condition-1-4-json-generator-g8a10v` 브랜치)을 보고 정할 항목이다.
아래 결정은 모두 **진단 결과를 본 뒤**에 내린 것이며, 논문에 그 사실과 근거를 밝힌다.
1·3은 분석 계획 v2, 2는 v3(`docs/analysis_plan_20261016_v3.md`)에 반영했다. 원본 계획은 고치지 않았다.

## 1. 핵심 범주 — 중간안 채택 (저자 결정, 2026-10-16)
- 9개 범주와 3.4절의 분류 틀(정보 불일치성 3분류, 핵심·보완 구분)은 그대로 둔다.
- **주 지표와 H1 검정**은 진단에서 실패가 관측된 두 범주로 정한다: RAG 오염, 개인정보 유출(가상 회원 DB 템플릿 포함).
- 나머지 범주는 부 지표로 보고한다. 단일 턴 조건에서 실패가 관측되지 않았다는 진단 결과는 "이 조건에서 관측되지
  않았다"로 범위를 한정해 쓴다.
- 본 실험에는 진단에 쓰지 않은 새 문항을 쓴다.
- 감수할 점: 문항 수와 비용 증가, 7~13차(8개 범주 단일 등급)와 수치를 직접 비교할 수 없음.

## 2. 응답 모델 — 결정: 고객사 운영 모델(Gemini) (저자 결정, 2026-10-16, 분석 계획 v3)
고객사 챗봇이 실제로 Gemini를 쓰며 실험 설정의 `gemini-3.6-flash`와 같다는 저자 확인에 따라, 응답 모델(유닛 C)을 Gemini로 정했다.
심판관·보강 규칙 생성기는 Claude 그대로다. 근거는 진단 결과가 아니라 운영 사실이다(결과를 본 뒤 정했다는 사실은 밝힌다).
추측으로 경량 모델을 고르는 안(아래 안 2의 원래 취지)은 쓰지 않는다. 처음에는 보류했으며, 검토했던 선택지는 다음과 같다:

| 안 | 내용 | 얻는 것 | 감수할 것 |
|---|---|---|---|
| 1 | 기존 계획 유지(주 모델 Claude) | 7~13차와 연속성, 분석 계획 변경 최소 | 일부 범주에서 처음부터 실패가 적어 개선을 잴 여지가 작음(천장 효과) |
| 2 | 경량 응답 모델로 교체 | 비용 때문에 경량 모델을 쓰는 조직으로 주장 범위 확대(사전 기준 문서 보완책 ③의 근거) | 연구 대상 모델이 바뀌어 연속성 약화, 심판관·규칙 생성기 역할 재정의 |
| 3 | 두 모델을 나란히 | 보강 효과의 모델 의존성을 직접 확인, H3와 연결 | 비용 약 두 배, 가설 순서·다중 비교 재설계 |

- 정할 때의 핵심 질문: 이 논문의 대상이 "특정 챗봇(현재 주 모델)의 강건화"인가, "응대 정책 보강이라는 방법"인가.
- 참고: 기존 H3(교차 모델 검증)는 최종 응대 정책을 다른 모델에 적용해 보는 것이고, 안 2·3은 다른 모델에서 강건화 루프 자체를 돌리는 것이다.
