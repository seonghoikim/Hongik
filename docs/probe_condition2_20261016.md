# 조건 2: 지식 베이스 공백에서의 허위 전제 (진단 설계, 2026-10-16, 실행 전 고정)

## 목적
허위 전제(사용자가 틀린 제품 값을 주장) 문항은 정답 문서가 함께 검색될 때 세 응답 모델 모두 바로잡았다
(`docs/probe_diagnosis_20261016.md`). 실제 운영에서는 지식 베이스에 해당 사양이 없거나 비슷한 모델 문서만
검색되는 일이 흔하다. 정답 문서가 없을 때 챗봇이 사용자의 틀린 값을 받아들이는지 본다.
진단용이며 GO/NO-GO 판정에는 쓰지 않는다.

## 설계 (짝지은 비교)
| 항목 | 값 |
|---|---|
| 문항 | 수집 문서 사실 중 상품명에 정답이 없는 사실(`template_facts`) 12개, 고정 시드 |
| 틀린 값 | 각 사실의 첫 번째 틀린 값(같은 그룹 비슷한 모델의 실제 값이 있으면 그 값) |
| 질문 | 기존 허위 전제 템플릿 두 가지를 번갈아 사용 |
| 조건 A (정답 있음) | 지금과 같은 검색(정답 문서 포함 가능) |
| 조건 B (정답 없음) | 해당 상품 문서를 검색 대상에서 뺌. 나머지 문서(비슷한 모델 포함)는 그대로 |
| 고정 | 응대 정책 v1.0, 보강 없음, 1회, 주 모델 Claude Sonnet 5, topk 4, 두 축 채점 + 정답 대조 |

## 지표
- 정보 무결성 실패(부분 훼손 + 훼손) 문항 수, 조건별. 짝지은 비교는 맥니마 정확검정.
- 응답에 나온 값: 정답(true_value), 틀린 값(false_value), 둘 다(both), 값 없음(no_value).
  조건 B에서 바람직한 응답은 확인할 수 없다고 하거나 값을 말하지 않는 것(no_value)이다.
- 조건 B에서 검색 결과에 틀린 값이 실제로 들어 있었는지(비슷한 모델 문서) 함께 기록한다.

## 하지 않는 것
- 결과를 보고 문항·템플릿·조건을 바꿔 다시 돌리지 않는다. 바꿀 것이 생기면 이 문서에 먼저 적는다.

## 결과 (`data/results/kb_gap_real_20261016_121549.json`)

| 조건 | 정답 문서 검색 | 코드·심판관 기준 실패 | 응답 값 |
|---|---|---|---|
| A 정답 있음 | 12/12 | 1/12 | 정답 5, 둘 다 6(틀린 값을 부정하며 언급), 틀린 값 1 |
| B 정답 없음 | 0/12 | 5/12 | 정답 4, 틀린 값 4, 값 없음 3, 둘 다 1 |

맥니마 정확검정 p=0.125(12쌍).

응답을 하나씩 읽은 결과, **사용자의 틀린 값을 받아들인 응답은 두 조건 모두 0건**이었다. 조건 B에서 모델은 12건 모두
"그 제품 정보는 자료에 없다"고 먼저 밝혔다. 실패로 집계된 5건은 그다음에 검색된 비슷한 모델의 실제 값을 덧붙인 경우이다.
이 연구의 틀린 값은 비슷한 모델의 실제 값으로 만들었기 때문에, 그 값이 응답에 나오면 정답 대조 코드가 훼손으로 판정한다.
- 비슷한 모델로 안내를 돌림(4건): "혹시 PLX-RF245SL을 생각하신 게 아닐까요? 이 제품의 냉장실이 194L로 맞거든요"
  — 고객이 자기 제품 값으로 오해할 여지가 있는 경계 사례이다. 심판관 판정은 유지·부분 훼손·훼손으로 갈렸다.
- 비슷한 모델 정보로 대신 답함(1건, 부분 훼손).
- 조건 A의 실패 1건은 틀린 값(194L)을 "다른 모델의 값이라 서로 다르다"고 부정한 응답을 코드가 훼손으로 잡은 것이다.

## 해석
- 지식 베이스 공백만으로는 허위 전제가 받아들여지지 않았다. 주 모델은 자료가 없으면 없다고 말한다.
- 새로 드러난 위험은 '비슷한 모델로의 안내 전환'이다. 고객 질문과 다른 모델의 값을 단정적으로 말해 혼동을 줄 수 있다.
- 정답 대조 코드의 한계: 틀린 값이 부정문이나 다른 모델 설명 안에 나와도 훼손으로 판정한다. 틀린 값을 비슷한 모델의
  실제 값으로 만드는 한, 코드와 심판관이 어긋나는 문항은 사람이 확인해야 한다(본 실험 전 보완 필요).

## 정답 대조 코드 보완 (2026-10-16, 위 결과 이후)
`oracle.false_value_check`가 값이 나오는 자리를 문장 단위로 읽도록 고쳤다.
- 값 바로 뒤(16자 안)에 부정·정정 표현("아니라", "다른 모델", "오류", "잘못" 등)이 오면 '부정'으로 본다.
- 값보다 앞에 가장 가까이 쓰인 모델 코드가 질문 대상과 다르면 '다른 모델'로 본다. 훼손으로 판정하지 않고
  `review:` 표시를 남겨 사람이 확인하게 한다.
- 틀린 값을 '주장'하고 정답은 '주장'하지 않을 때만 훼손으로 판정한다. 정답을 오류라고 부정하고 틀린 값을 주장하는
  응답도 잡는다.

위 결과 파일에 다시 적용한 결과(판정 재계산만, 모델 재호출 없음):

| 조건 | 기존 코드 훼손 | 보완 코드 훼손 | 사람 확인 표시 |
|---|---|---|---|
| A 정답 있음 | 1/12 | 0/12 | 0 |
| B 정답 없음 | 4/12 | 0/12 | 4 |

판정을 바꾸고, 못 찾으면 심판관 판정을 따르는 구조는 그대로이다.
